# Verifying published artifacts

## Purpose

Verify a release's artifacts **before** you deploy any of them: the
cosign **keyless** signature and SPDX SBOM attestation on the GHCR image,
the checksums on the `.deb` / Arch package / archives, and the scanner
verdicts that the release run recorded. Verify first, run second —
nothing in this repo ships a private key, so the signature is the trust
anchor (docs/release.md, "Hard rules").

## Preconditions

- `cosign` on PATH (`pacman -S cosign`; the publish pipeline pins its own
  version in `.github/workflows/publish.yml`). Keyless verification needs
  no key material and no credentials — it checks the Sigstore certificate
  (Fulcio) and the transparency-log entry (Rekor) against the workflow
  identity.
- The artifact identity you are verifying: the tag (`:edge`,
  `:sha-<short>`, or a `vX.Y.Z` release tag) or the digest recorded in the
  run's evidence bundle (`artifacts/<run-id>/manifest`, docs/release.md
  §7).
- For local/snapshot artifacts: the `dist/` of that build with its
  `checksums.txt`.

## Steps

1. **Verify the image signature** (docs/release.md §2.4). The signature is
   bound to the publish workflow's Sigstore identity — verify against that
   identity, not "any signature":

   ```sh
   cosign verify \
     ghcr.io/dbirks/game-narrator:edge \
     --certificate-identity-regexp 'https://github.com/dbirks/game-narrator/.github/workflows/publish.yml@.*' \
     --certificate-oidc-issuer https://token.actions.githubusercontent.com
   ```

   For a tagged release, replace `:edge` with the tag (e.g. `:v1.2.3`);
   for a pinned digest, verify `ghcr.io/dbirks/game-narrator@sha256:…`
   (the digest from the run's manifest) instead of a tag — tags move,
   digests do not.

2. **Check the SBOM attestation** that rides alongside the signature —
   the SPDX document generated by goreleaser/syft for the amd64 archive,
   attached by the publish job:

   ```sh
   cosign verify-attestation --type spdxjson \
     ghcr.io/dbirks/game-narrator:edge \
     --certificate-identity-regexp 'https://github.com/dbirks/game-narrator/.github/workflows/publish.yml@.*' \
     --certificate-oidc-issuer https://token.actions.githubusercontent.com
   ```

   The attestation names the exact archive
   (`game-narrator_<version>_linux_amd64.tar.gz`), its SHA-256, and every
   Go module with its version — so a supply-chain question ("which
   `stdlib`/module set is in this build?") is answerable from the
   registry alone, without pulling the image.

3. **Verify the package/archive checksums** for the `.deb` and the Arch
   `*.pkg.tar.zst` (and the `.tar.gz` archives) from the same run:

   ```sh
   (cd dist && sha256sum -c checksums.txt)
   ```

   every line must be `OK` (docs/release.md §1: the snapshot pipeline
   writes `checksums.txt` alongside the artifacts).

4. **Read the recorded scanner verdicts** of the run before trusting the
   artifacts: the artifact scanner's output (files, `.deb` data+control,
   `.pkg` payload + metadata, and — for the `edge` job — the image's
   merged filesystem), the secret-scan verdict, and the smoke log with its
   NOT RUN reasons (docs/release.md §2.5 and §7). An image the scanner
   never judged is not a verified artifact.

5. **Then deploy** per docs/release.md §3: `.deb` on the appliance
   (`apt-get install ./…_linux_arm64.deb`, start the unit again after an
   upgrade), `sudo pacman -U --noconfirm <pkg>` on Arch, or pull +
   recreate the container with the same data volume.

## Verification

- `cosign verify` prints the verified claims for the identity and exits 0
  (it exits non-zero on any check failure — a missing signature is a
  failure, not a warning). Both commands above were run and passed
  against the published `edge` manifest on 2026-10-18.
- `cosign verify-attestation` returns the attestation's in-toto payload:
  subject = the image's manifest digest, predicate = the SPDX document.
- `sha256sum -c checksums.txt` reports `OK` for every artifact of the run.
- UNO Q remains **NOT VERIFIED** until the hardware smoke
  (`make test-hardware`, 13-uno-q-hardware-smoke.md) passes — verifying
  the signature and the SBOM does not change that (AGENTS.md rule 12).

## What NOT to do

- Do not skip the identity flags: a bare `cosign verify` against a
  self-made key would pass anything; the certificate-identity regexp +
  OIDC issuer is what pins the signature to *this* repo's publish
  workflow.
- Do not verify a tag and deploy a different ref — verify the exact tag
  or digest you are about to pull.
- Do not trust an artifact whose run's scanner/smoke evidence is missing
  (docs/release.md §7: the evidence bundle is part of the release, not
  optional).
- Do not treat a passing signature as an endorsement of the UNO Q
  hardware path: arm64 artifacts are cross-compiled and file-verified;
  execution on real ARM is the hardware gate's job.
