# ADR-0083: Developer inspector actions — corrections, trace fixtures, re-run, evidence export, utterance waveform

Date: 2026-10-19
Status: accepted
Owners: agent worker (gap G13)
Related requirements/tests: docs/spec/09 "Developer dashboard layout" (the nine buttons; "audio waveform"; "Link everything using trace_id"), docs/spec/08 API table (`POST /api/v1/corrections`, `POST /api/v1/dev/fixtures` "fixture recording and browsing"), docs/spec/12 (regression fixture discipline; frame replay), docs/spec/13 (evidence correlation), ADR-0024 (dev traces), ADR-0042 (redaction rules), ADR-0052 (corrections are the regression fixtures), ADR-0054 (external fixture root), `TestOpenAPIDocMatchesTheRouter`, `TestRoleMatrixOverEveryRoute`, `web/e2e/developer-actions.spec.ts`

## Context and constraints

docs/spec/09's developer dashboard layout names, per observed event/utterance: the six correction buttons ("speaker incorrect", "text incorrect", "wrong region", "not narratable", "duplicate", "prediction misfire"), "save regression fixture", "re-run against current model", "download evidence", and an audio waveform. The gap audit (G13) records that the inspector pins frame/crop/OCR/trace (ADR-0024) but offers none of the actions: corrections exist only from the message editor (ADR-0052), there is no per-trace fixture capture, no re-run, no evidence export, and no waveform anywhere in the UI.

Four constraints governed the design:

1. **No schema change.** The `corrections` table (0002) already has the label shape (kind, target, before/after, evidence JSON, actor, review state) and ADR-0052 made it the regression fixture. Adding a `trace_id` column would require a forward migration and a backup/restore test (AGENTS.md rule 10) for what the `evidence` JSON column exists for ("frame/observation ids, asset hashes" — ADR-0052 decision 4). The correlation ids ride in `evidence` as a typed member.
2. **No simulation theater (rule 3).** The "re-run against current model" must recompute something real and must say exactly which decision path it recomputed. A re-run that pretends to re-invoke the model provider would be the lie the rule forbids; the route recomputes the local decision path (matcher index built from the profile's content, the current build's scoring) and reports the recorded provider adjudication as recorded, not re-invoked.
3. **Fixtures never enter the repository (rule 5).** Frames, OCR text and game script are evidence, not source. The fixture root is the documented external one: `$GAME_NARRATOR_FIXTURE_DIR`, defaulting to the gitignored `artifacts/fixtures` tree (ADR-0054's convention; the bench and the dolphin scenario harness already read fixture directories from exactly this root).
4. **Roles are the privacy boundary.** Everything new sits under `/api/v1/dev`, whose scope grant is developer-only (the event payloads and the stored frames are the sensitive tier docs/spec/08 reserves for the developer role). The correction writes go through the existing curator-and-up `POST /api/v1/corrections`.

## Decision

1. **The six correction buttons record `corrections` rows through `POST /api/v1/corrections`** — the same route ADR-0052 named for "the inspector's 'speaker incorrect / text incorrect / …' actions". The mapping (UI label → domain kind, target) is:
   - "speaker incorrect" → kind `speaker`, target the committed message;
   - "text incorrect" → kind `text`, target the committed message;
   - "wrong region" → kind `region`, target the observed region (kind/region coupling is the domain's own constraint);
   - "not narratable" → kind `classification`, target the committed message;
   - "duplicate" → kind `other`, target the committed message, reason "duplicate";
   - "prediction misfire" → kind `other`, target the committed message, reason "prediction misfire".
   The label's `before_value` is the observation's reading, or, for `speaker`, the committed speaker id when the commit's payload carries one (the ADR-0052 domain's own constraint: a label records what was wrong, and the speaker label's `before` is the id it was wrong about); `after_value` is empty — a label records the mistake, it never applies a fix (ADR-0052 decision 4). When the occurrence has no commit yet, the label targets the occurrence itself (`target_type` `other`, `target_id` the `dialogue_occurrence_id`) rather than being refused: the mistake was observed, and the label must outlive the rows it is about. The correlation ids ride the `evidence` member as typed string entries (the column's shape, ADR-0052's "frame/observation ids, asset hashes"): `trace:<trace_id>` first, then `occurrence:<dialogue_occurrence_id>` and `message:<message_id>` when present. The `trace:<trace_id>` entry is the member the inspector's action bar filters on (it lists a trace's recorded labels by scanning the bounded profile correction list for it, newest first), the fixture's `corrections.json` and the evidence bundle's `corrections.json` are built by the same scan, and it is how a future bench consumer finds a label's provenance.
2. **"Save regression fixture" is `POST /api/v1/dev/fixtures`** with body `{"trace_id": …}` — docs/spec/08's "fixture recording" route (the `GET /api/v1/dev/fixtures` browsing half already exists, ADR-0052). The handler reads the trace's persisted envelopes and writes one **trace fixture** under the external fixture root at `<root>/trace-fixtures/<fixture id>/`:
   - `manifest.json` — schema 1: fixture id, `kind: "trace-fixture"`, created_at, the source correlation block (trace/session/profile/occurrence ids, event seqs), the profile revision the observation ran under, and a sha256 manifest of every other entry (the manifest cannot carry its own hash; the same integrity shape as ADR-0054 and the support bundle);
   - `observation.json` — the stored observation: raw and normalised text, OCR confidence, text state, region, scene, generation, frame seq;
   - `expected.json` — what the recorded run produced: the ranked candidates (ids, probabilities, components), the commit (message, speech eligibility, reason, speaker) and the recorded decision (provider, model, request id, outcome) when the trace carries one;
   - `speech.json` and `speech/utterance.wav` — when the trace's utterance audio is still in the speech cache (its `cache_key` rides the `speech.ready` event): the utterance's identity and the played bytes;
   - `frames/` — the stored full-frame and ROI crop bytes when the dev-trace store still holds them (the manifest carries their hashes);
   - `corrections.json` — the labels linked to the trace at save time.
   The answer is 201 with the fixture id, the directory the fixture landed in (the operator can see exactly where the evidence left the machine) and the entry manifest. The fixture is a per-occurrence regression sample, not a dolphin drive fixture: the bench's captured-replay gate (ADR-0054/0058) consumes drive fixtures (frame list + `truth.json` + `profile.json`), and a trace fixture does not pretend to be one — it is the unit docs/spec/08's "fixture recording" and the /tests harness's fail-only re-runs (ADR-0052 decision 3) read, and it is self-contained: replayable by re-running the stored observation (decision 3) and gradable against `expected.json`.
3. **"Re-run against current model" is `POST /api/v1/dev/traces/{trace_id}/rerun`** (no body). The handler rebuilds the matcher index from the session's profile revision content via the store (the published revision is immutable, so this is the same corpus the run used, scored by the current build's matcher — the honest meaning of "current model" for the local decision path) and re-ranks the trace's last stored `text.observed` (its raw text, OCR confidence, prefix flag from the text state, scene from the trace's ranking). The answer is 200 with the previous ranking (from the stored `message.candidates`), the current ranking, a per-candidate diff (rank and probability delta) and a `decision` note: whether the recorded trace involved a provider adjudication, and that this route recomputes the local path only — the model is not re-invoked, because the session's decision wiring is fenced per session (generations, at-most-one-in-flight, event emission on the session chain) and a re-invocation outside those fences would be a different call than the one the run made. Re-running the session's replay is the model's own re-run; this route is the cheap half, and it says so.
4. **"Download evidence" is `GET /api/v1/dev/traces/{trace_id}/evidence`**: one tar.gz (gzip-compressed tar, the same archive shape the support bundle ships) with `manifest.json` (redaction rules applied, entry hashes, correlation block), `events.json` (every persisted envelope of the trace; each string value passes `internal/support`'s redaction rules — URLs, bearer/authorization material, bare API keys, private IPs, home paths, email addresses), `assets/frame-…` / `assets/crop-…` (the stored samples, when present) and `speech/utterance.wav` (when resolvable), plus `corrections.json`. The bundle is `application/gzip` with an attachment name and `no-store`. Unlike the ADR-0042 support bundle — which must never leave the machine with game text, frames or waveforms because it goes to external support — this is the developer's explicit export of the tier that role may already see on the page (docs/spec/08: developer mode "can display sensitive gameplay text and provider traces"), redacted of credentials and network identity, and docs/spec/09's "session export explicit" is the gate: the download is a deliberate click, never automatic.
5. **The utterance audio is `GET /api/v1/dev/speech/audio?cache_key=…`**: the `speech.ready` event of the occurrence carries the cache key, and the route reads the same `speech.Cache` instance the session's playback used (the voice service the API already wires for `/api/v1/voices`), serving the stored WAV as `audio/wav` with `no-store` and the entry's SHA-256 as the ETag (the voice audition audio's pattern). 404 covers evicted and never-stored keys alike; 503 the unwired-voice-service case. The developer page renders it as a **waveform**: the bytes are fetched, the PCM16 is decoded in the browser (RIFF — the documented format), reduced to per-column peak amplitudes (the maximum absolute sample per bucket — the shape the eye reads, not a spectrogram the inspector does not promise), and drawn to a canvas next to a same-origin `<audio>` element that plays the same served bytes. Canvas drawing is CSP-safe (`script-src 'self'`, no inline scripts; the `style-src-attr` exception the DetailPanel already relies on). When the occurrence's utterance was skipped (no approved voice, backpressure, mute) or the cache entry is gone, the panel says so with the reason the events carry instead of showing an empty canvas.
6. **Roles and contract.** All four new routes sit under the existing developer-only `/api/v1/dev` grant; the correction writes ride the existing curator grant. The OpenAPI document gains the four operations (`recordFixture`, `rerunTrace`, `getTraceEvidence`, `getSpeechAudio`), and the TS types are regenerated from it.

## Options considered

- **A `trace_id` column on `corrections` plus a migration.** Rejected: rule 10 makes the cost real (forward migration, backup/restore test, index), while the `evidence` JSON column exists precisely for correlation ids and the domain already declares `target_id` a loose reference that outlives its rows.
- **Invoking the decision provider from the re-run route.** Rejected (see constraint 2 and decision 3): it would bypass the session's fences and the one-in-flight bound, emit events on a dead chain, and spend a model call the user did not ask to pay for. The response's `decision` note and the UI's "local path" label keep the boundary visible.
- **A separate `regression_fixtures` table for saved fixtures.** Rejected twice already (ADR-0052: the corrections table; ADR-0054: the fixture is a golden file outside the repo). The trace fixture file complements, not duplicates, both: the label rows are the assertions, the file is the replayable observation.
- **Streaming the evidence as a directory listing + per-file fetches.** Rejected: an export must be one artifact with one hash manifest, the way the support bundle and the dolphin scenarios' reports are — a developer forwarding the bundle names one file.

## Consequences and risks

- The inspector's action bar is only as good as the stored trace: an evicted dev-trace sample degrades the fixture (`frames/` absent, the manifest says so) and the waveform degrades to the reason text; both are the documented degraded modes, not failures.
- Fixture writes are local filesystem writes under the configured root: no quota here (a trace fixture is one observation: a JPEG, a crop, a WAV at most), and the directory is append-once by id (ULIDs never collide), so concurrent saves cannot overwrite.
- The redaction rules are the support package's: they catch credentials and network identity, not game text — which is deliberate for this bundle (decision 4). The UI labels the export as containing gameplay text.
- A re-run on a profile whose edition republished since the run is a re-run of the run's revision (immutability), not of the new revision; a developer comparing revisions re-runs the new revision's session.

## Verification

- `internal/api` (`dev_actions_test.go`): fixture recording writes the documented files under a temp fixture root (the manifest hashing every entry, the observation/expected contents, the frame and the WAV when the dev store and the speech cache hold them) and refuses a trace with no observation; the re-run answers previous == current for an unchanged profile and reports the recorded provider involvement; the evidence bundle is a valid tar.gz whose entries hash to the manifest and whose `events.json` keeps the gameplay text while the redaction walker (unit-tested on planted credentials, hosts, private IPs, home paths and emails) is the rule set every string passes; the speech audio route serves the cached WAV with its ETag and answers 404/400/503. The authz matrix and the OpenAPI router/scope drift tests pass with the four new operations.
- Playwright (`web/e2e/developer-actions.spec.ts`, the dedicated `developer-actions` project — the packaged binary with the replay allowlist and the speech roles at the scripted TTS instance, so the utterance has a voice (the seed's lines carry no speaker, so the narrator voice — the session's fallback for unattributed lines — is registered; the decision role also points at the scripted Clef instance, though this seed commits locally and never calls it; it cannot share the `developer-decision` server because that spec claims the appliance unconditionally): after a real replay session with a registered Marina voice, pinning the page-1 commit's trace records labels through the panel that are visible in `GET /api/v1/corrections` with the trace's correlation in their evidence; "save regression fixture" answers the fixture directory and the spec verifies the on-disk manifest and expected contents; "re-run against current model" renders the diff with the winner held; "download evidence" downloads a named tar.gz whose untarred entries include the event log, the manifest and the utterance WAV; the utterance waveform canvas is painted and the audio element is addressed by the trace's cache key.

## Rollback / migration

No schema change. Rollback: delete the four routes and handlers, the OpenAPI operations, the inspector's action bar and waveform, and the regenerated TS types; written trace-fixtures and recorded labels are inert (the fixture directories are outside the repo by design, and label rows of kinds the new UI records are already valid `corrections` rows ADR-0052's views serve).
