# ADR-0053: Optional Arch package (.pkg.tar.zst) alongside the .deb

Date: 2026-10-18 (amended 2026-10-18: per-format Arch dependency names; real install re-run without `--nodeps`; amended 2026-10-18: data-dir mode corrected to 0700 per ADR-0063 — the 0750 lines below record the state as shipped, not the current one)
Status: accepted
Owners: agent worker
Related requirements/tests: docs/spec/15 ("OS packages: .deb for UNO Q and optional Arch package; nFPM integration through GoReleaser"; "Publishing restrictions" — scanner scope), docs/spec/16 M8 ("Create systemd/nFPM Debian package, optional Arch package"), docs/spec/10 ("UNO Q software deployment" — dedicated user, /var/lib/game-narrator state, 0600 env), docs/release.md sections 1, 3, 5, 8, AGENTS.md rules 5 (provenance) and 12 (no fake acceptance), builds on ADR 0033 (GoReleaser/nfpm pipeline, .deb packaging, artifact scanner), ADR 0006 (multi-arch strategy)

## Context and constraints

- docs/spec/15 lists the Arch package as *optional* and requires it to be built through the existing nFPM/GoReleaser pipeline, install-smoked, and scanned like every other artifact ("avoid claiming support without install smoke").
- The .deb is the primary UNO Q path and is field-verified (device lifecycle, bookworm container smoke, `dpkg-deb` assertions in `scripts/release/smoke.sh`). Its behaviour must stay identical: the task and AGENTS.md rule 12 both forbid silently reworking the verified path.
- GoReleaser 2.14 + nfpm v2.45 (installed versions, verified from source in `/tmp/goreleaser-2.14.0` and the nfpm v2.45.0 module sources):
  - One `nfpms` entry can build multiple `formats`; `overrides.<format>` merges per-format `scripts` and `contents` (mergo replacement of the contents slice), and `archlinux.scripts.preupgrade/postupgrade` exist only for the Arch format.
  - The Arch packager wraps the shared `scripts` (postinstall/preremove/postremove) and the arch-specific postupgrade into a single `.INSTALL` (`function <name>() { … }`); pacman 7.1 (PKGBUILD(5)) runs install hooks on fresh installs and remove hooks on removals **only** — on upgrades only `pre_upgrade`/`post_upgrade` run.
  - The Arch packager computes `.PKGINFO` `pkgver` as `Version-Release` and includes the version prerelease **only** when `Epoch` is set; goreleaser 2.14 fills `Epoch`/`Release`/`Prerelease` from the top-level nfpms entry only (per-format overrides of them are silently ignored).
- A real install test is required on this Arch amd64 host (passwordless sudo available). The host's sync databases (core+extra) contain every required runtime dependency under its **Arch** name (`pacman -Si`, verified 2026-10-18: `ffmpeg`, `tesseract`, `tesseract-data-eng`, `v4l-utils` in extra; `ca-certificates` in core). The shared nfpms `dependencies` list originally carried the **Debian** names `tesseract-ocr`/`tesseract-ocr-eng`, which do not exist in any Arch repository — the first build therefore failed `pacman -U` dependency resolution ("could not be found"). The fix is per-format dependency names (see Decision), not host-repo changes or `--nodeps`.

## Options considered

1. **Second `nfpms` entry for Arch (shared scripts for both formats)** — rejected: nfpm maps the shared `scripts` onto both formats, so the deb's `postrm` `$1 = "3"` (remove-or-purge) check would silently never run on Arch (pacman passes the old version string, never `"3"`), and the deb and the .pkg would share maintainer scripts that encode dpkg-specific argument semantics.
2. **One `nfpms` entry, `formats: [deb, archlinux]`, with `overrides.archlinux` swapping scripts/contents and `archlinux.scripts.postupgrade`** — chosen: the .deb keeps the exact shared scripts (`packaging/deb/*.sh`) it has always used; the Arch format gets dedicated hooks (`packaging/arch/*.sh`) written for pacman's hook contract.
3. **User/directory creation: scripted `useradd`/`install -d` in the hooks (deb parity) vs. declarative `sysusers.d`/`tmpfiles.d` files vs. both** — chosen: ship `packaging/sysusers.d/game-narrator.conf` + `packaging/tmpfiles.d/game-narrator.conf` in **both** formats (the deb does not ship them today), and have the Arch hooks apply the user definition immediately (`systemd-sysusers`, `useradd` fallback) while setting directory ownership with `install`/`chown`. Rationale below.

## Decision

- `.goreleaser.yaml`: one `nfpms` entry, `formats: [deb, archlinux]`.
  - **Per-format dependencies**: the shared `dependencies` list keeps the Debian names (`ffmpeg`, `tesseract-ocr`, `tesseract-ocr-eng`, `v4l-utils`, `ca-certificates`) for the .deb; `overrides.archlinux.dependencies` lists the Arch names (`ffmpeg`, `tesseract`, `tesseract-data-eng`, `v4l-utils`, `ca-certificates`). goreleaser 2.14's `mergeOverrides` applies the per-format override with `mergo.WithOverride`, which replaces slice fields, so the Arch package's `.PKGINFO` gets exactly the Arch list and the .deb's `Depends` is byte-unchanged. Verified 2026-10-18: `pacman -U` without `--nodeps` resolves all five (all present on the host from core/extra) and the install transaction reports `Depends On: ffmpeg tesseract tesseract-data-eng v4l-utils ca-certificates`.
  - Shared `scripts` = `packaging/deb/*.sh` (deb unchanged). `overrides.archlinux.scripts` = `packaging/arch/post_install.sh`, `pre_remove.sh`, `post_remove.sh`; `archlinux.scripts.postupgrade` = `packaging/arch/post_upgrade.sh`. `packager` metadata set.
  - `overrides.archlinux.contents` is the full Arch file list (mergo replaces the slice): same files as the base list, except the unit at `/usr/lib/systemd/system/` (on Arch `/lib` is a symlink owned by the `filesystem` package; a package entry for `/lib/` is a hard pacman file conflict), plus an explicit `/etc/game-narrator` dir entry (root:game-narrator 0750) so the package metadata matches the hook's result and pacman does not warn "directory permissions differ".
  - `packaging/sysusers.d/game-narrator.conf` (`u game-narrator … /var/lib/game-narrator /usr/sbin/nologin`) and `packaging/tmpfiles.d/game-narrator.conf` (`d /var/lib/game-narrator 0750 game-narrator:game-narrator -`, `d /etc/game-narrator 0750 root:game-narrator -`) are shipped in both formats. **The .deb's behaviour is unchanged and intentionally kept identical**: its postinst still creates the user with `useradd` and the directories with `install -d`; the conf files are inert without systemd (the bookworm container smoke runs systemd-free) and idempotent under systemd (the user/dirs already exist with the same attributes). This is the "sysusers/tmpfiles for both formats" option with the explicit constraint that the verified .deb path is not reworked. *(Superseded for the data directory: ADR-0063 (same day) corrected the `/var/lib/game-narrator` mode from 0750 to 0700 across all packaging surfaces, per docs/spec/02 and ADR-0014; the `/etc/game-narrator` 0750 entry remains. The 0750 above is preserved as the as-shipped record.)*
  - **`/var/lib/game-narrator` is deliberately not a package entry in either format**: it is user data (docs/spec/15, docs/release.md section 5) and is created/owned by the maintainer scripts/hooks. A package-owned data dir would make removal semantics ambiguous (pacman `rmdir` on a non-empty dir) and weaken the "never deleted by the package" guarantee.
- Arch hook semantics (pacman 7.1), mirroring the deb scripts:
  - `post_install` (fresh installs) / `post_upgrade` (upgrades; install/remove hooks do NOT run on upgrades): user via `systemd-sysusers` from the shipped sysusers.d file (with `useradd` fallback), data/config directories via `install`/`chown`, config.yaml 0640 root:game-narrator, env-file hint, `systemctl daemon-reload`. `post_upgrade` additionally stops the unit (graceful drain) — the deb's `prerm` does the same on upgrade — leaving the unit STOPPED across the upgrade (docs/release.md section 3 contract; the operator starts it to pick up the new binary).
  - `pre_remove`: `systemctl stop` (deb `prerm` parity). `post_remove`: `systemctl disable` + `daemon-reload` (deb `postrm` remove-or-purge parity; pacman has no purge verb, so it runs on every removal). The data directory and the sysuser are intentionally NOT removed (docs/release.md section 5).
- Directory ownership is set with `install`/`chown` (libc NSS), **not** `systemd-tmpfiles`, inside the hooks: on the test host `systemd-tmpfiles` cannot resolve any non-root user name (see Validation). The shipped tmpfiles.d file remains the boot-time enforcer (`systemd-tmpfiles-setup.service`).
- `scripts/release/scan-artifacts.sh`: `*.pkg.tar.zst` artifacts are extracted (payload **and** `.PKGINFO`/`.MTREE`/`.INSTALL` metadata) and scanned with the same rules as archives/.debs; checksums cover them automatically (goreleaser checksum pipe).

## Tradeoffs

- **Flat `pkgver` (`0.0.0-1`) for all snapshot builds**: provenance lives in the artifact name + checksums, not in `pacman -Qi`; version-ordered "downgrade" detection is unavailable (same caveat class as the deb's lexicographic-SHA ordering). Accepted: per-format epoch/release is impossible in goreleaser 2.14 without changing the .deb's version, and a same-version `pacman -U <file>` re-installs (verified), so upgrades between any two snapshot builds work.
- **Hook duplication**: `post_install` and `post_upgrade` carry the same setup body (pacman calls exactly one of them per operation). Deliberate: each hook stays self-contained and robust (no cross-file sourcing from the package).
- **Deb carries two inert conf files**: +2KB of package contents and two `dpkg-deb --contents` lines; verified inert (no systemd in the container smoke) and idempotent under systemd. Chosen for one declarative source of truth across formats, per the task's "prefer sysusers/tmpfiles for both formats if cleaner, but keep the deb behaviour identical and say so".
- **Upgrade stop timing**: on the deb the unit stops *before* file replacement (`prerm`); on Arch it stops in `post_upgrade`, *after* extraction. The running process keeps its old binary inode during extraction (safe on Linux); the drain still happens before the next start. Documented, accepted.

## Validation

All on the Arch amd64 dev host, from a clean worktree build (`git worktree add --detach /tmp/gn-arch-2ef5bc5 HEAD` + the task's changed files overlaid; `goreleaser release --snapshot --clean`, version `0.0.0-snapshot-2ef5bc5`):

1. `goreleaser check` passes; artifact list includes `game-narrator_0.0.0-snapshot-2ef5bc5_linux_{amd64,arm64}.pkg.tar.zst` plus both `.deb`; `checksums.txt` covers all four and `sha256sum -c` passes.
2. `.pkg.tar.zst` internals (amd64): `.PKGINFO` (`pkgname=game-narrator`, `arch=x86_64`, `pkgver=0.0.0-1`, five `depend=` lines, `backup=etc/game-narrator/config.yaml`), `.MTREE` (unit 0644, config.yaml 0640, env.example 0640, conf files 0644, binary 0755; no `/lib` entry), `.INSTALL` (four functions with the hook bodies).
3. `scripts/release/scan-artifacts.sh` PASS over all six artifacts (new `.pkg.tar.zst` extraction path scans payload + metadata); `--self-test` still PASS (planted `/home/<user>` caught, redactor pattern not flagged).
4. Deb identity vs. the previous build's `.deb` (c624602): `postinst`/`prerm`/`postrm`/`conffiles` byte-identical; `control` differs only in `Version` (SHA) and `Installed-Size`; data tree differs only in binary size and the two added conf files.
5. ~~Real install with `--nodeps --nodeps` (first build, 2ef5bc5): superseded~~ The first build's `.PKGINFO` carried the Debian names `tesseract-ocr`/`tesseract-ocr-eng` in `depend=`, so `pacman -U` without `--nodeps` failed dependency resolution (initially misdiagnosed as a missing `community` repo on the host — wrong: `pacman -Si tesseract` resolves from `extra`). After the `overrides.archlinux.dependencies` fix, **real install without `--nodeps`** on the rebuilt snapshot (`bc9e690`): `sudo pacman -U --noconfirm <amd64 .pkg.tar.zst>` → `resolving dependencies…` with no error, rc=0; verified: `pacman -Qi` (installed, x86_64, 0.0.0-1, `Depends On: ffmpeg tesseract tesseract-data-eng v4l-utils ca-certificates`), sysuser `game-narrator:x:965:965:Game Narrator service:/var/lib/game-narrator:/usr/sbin/nologin`, group `game-narrator`, `/var/lib/game-narrator` `game-narrator:game-narrator 750`, `/etc/game-narrator` `root:game-narrator 750`, `config.yaml` `root:game-narrator 640`, unit at `/usr/lib/systemd/system/game-narrator.service` visible to `systemctl`, `/usr/bin/game-narrator version` → `game-narrator 0.0.0-snapshot-bc9e690 (…)`. ## Reversal plan

- Remove `archlinux` from `formats`, the `overrides.archlinux` and `archlinux:` blocks, and the two conf-file contents entries in `.goreleaser.yaml`; delete `packaging/arch/`, `packaging/sysusers.d/`, `packaging/tmpfiles.d/` and the scanner's `*.pkg.tar.zst` loop. The .deb pipeline returns to its ADR 0033 state; the deb identity check in Validation 4 is the regression guard.
- If a future goreleaser exposes per-format epoch/release, embed the SHA in `pkgver` (drop the flat-version note) rather than changing the version scheme globally.
