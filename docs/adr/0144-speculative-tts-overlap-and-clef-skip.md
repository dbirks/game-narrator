# ADR-0144: overlap speculative TTS with the Clef round trip, and skip Clef on confident local matches in the multi-box E2E

Date: 2026-10-21
Status: accepted
Owners: clef-skip worker
Related requirements/tests: docs/spec/05 (candidate retrieval → graph-aware scoring → optional Clef/VLM adjudication → commitment policy; "Fast LLM/VLM called only for unresolved OCR"), docs/spec/07 (the voice pipeline, the successor prewarm FR-11, and the singleflighted TTS cache), docs/spec/01 (deadline/cancellation propagation; immutable scene observations; the four fences), ADR-0050 (Clef adjudication in the pipeline — the `Decider` seam this extends), ADR-0055 (a Clef verdict selecting a retrieved candidate commits the line), ADR-0115 (§1 the escalation and the `NeedsAdjudication` policy this overlap leans on; §3 the perceptual skip), ADR-0136 (the unmatched read-through that reuses the same commit → speech route), `cmd/game-narrator/main.go` (the production `Margin: 0` the E2E tests now match), `TestLiveDecision` / `dolphin_live_test.go` (the live test that intentionally keeps `dolphinClefMargin = 0.99`)

## Context and constraints

Live runs pay an avoidable Clef latency on two counts:

1. **Every line blocks on Clef in the multi-box E2E.** `perchar_live_test.go` and `catchup_live_helpers_test.go` set `DecisionOptions.Margin = dolphinClefMargin` (`0.99`). `session.Config.NeedsAdjudication` returns true when `AdjudicateMargin > 0 && rank.Margin < AdjudicateMargin`, so at a threshold of `0.99` essentially *every* locally-accepted ranking is offered to Clef — even an exact or high-margin match the local matcher already settled. The production binary (`cmd/game-narrator/main.go`) leaves `Margin: 0`, so only an abstained or fuzzy-below-bar ranking consults Clef; a confident local match commits on the local evidence and skips the round trip entirely.
2. **The adjudication round trip is serial with the synthesis.** When `NeedsAdjudication(rank)` is true and `pipeline.Config.Decider.Decide` is called in the rank worker (`internal/pipeline/runner.go`), the pipeline waits `500–2000 ms` (the decision role's timeout) for Clef before the commit can drive TTS. Yet `rank.Candidates[0].MessageID` is already known *before* `Decide` starts. If the pipeline exposes a hook fired on the rank worker just before `Decide`, the runtime can synthesise the top candidate's line in the background *while* Clef is in flight. Because `speech.Cache.GetOrGenerate` is singleflighted, when Clef returns and the commit confirms the same `MessageID`, the commit's TTS request joins the in-flight generation or gets an instant cache hit.

Constraints: the commitment and the speech fences are the product's safety (docs/spec/01 invariant 2, ADR-0092, ADR-0057) — a speculative prewarm must schedule and play nothing until the commit occurs, and a Clef verdict that narrows away from the prewarmed line must cost at most one wasted synthesis, never a stale playback. The pipeline stays provider-free and speech-free (it holds no TTS client and no speech wiring — the same rule that keeps `Decider` and `OCRFallback.Secondary` seams, not implementations). The rank worker is already the one goroutine that both calls `Decide` synchronously and knows `rank.Candidates[0].MessageID`, so the hook belongs there, not in the session.

## Options

1. **Prewarm from the session's commit path only (no change).** Rejected: it is the status quo the user is asking to beat. The top candidate's synthesis starts only after Clef returns and the commit fires, so the full Clef round trip is serial ahead of the first TTS bytes.
2. **Prewarm the whole shortlist when adjudication is asked.** Rejected: it spends the TTS budget on every offered candidate (up to `DecisionCandidates`) for a line Clef will commit to one of. A verdict that narrows to the runner-up wastes the top-1 synthesis, and a five-candidate shortlist can spend five syntheses for one committed line. The singleflighted cache makes extra keys cheap-ish, but the byte quota and the provider's concurrency limiter are the product's budget, not a sink.
3. **A pipeline hook `OnAdjudicating(messageID)` fired on the rank worker just before `Decide`, wired to a single top-candidate prewarm (chosen).** The hook carries only `rank.Candidates[0].MessageID` (the one line the local matcher already ranked first — the line the commit most often confirms). The runtime wires it to `speechWiring.speculativePrewarm`, which spawns the *same* `prewarmWorker` the successor prewarm (FR-11) uses, so one synthesis per key and the same versioned cache key a later commit would use. The overlap is the point: the synthesis runs under the run's `endCtx` (cut at session end) while Clef is out, and the singleflighted cache collapses the two requests into one.

## Decision

1. **The pipeline seam.** `pipeline.Config` gains `OnAdjudicating func(messageID string)`. In `rankWorker`, immediately before `reply = r.cfg.Decider.Decide(...)`, and only when `r.cfg.Decider != nil && r.cfg.Reducer.NeedsAdjudication(rank)` (the existing gate — the hook is a no-op otherwise) and `len(rank.Candidates) > 0 && rank.Candidates[0].MessageID != ""`, the pipeline calls `r.cfg.OnAdjudicating(rank.Candidates[0].MessageID)`. The call is on the rank worker, synchronous, and strictly before the Clef call goes out — so by the time `Decide` runs the prewarm has already been dispatched. `nil` (the default) preserves the historic behaviour: the hook is a pure additive seam, and a harness that wires no hook runs exactly as before.
2. **The runtime wiring.** `Manager.Start` sets `cfg.OnAdjudicating` to a closure that reads the session's speech wiring through an `atomic.Pointer[speechWiring]` and calls `speculativePrewarm` on it. The atomic is because the speech wiring is built *after* the runner (it needs the runner), so the closure — fixed before `pipeline.New` — cannot name it directly; it reads the pointer the wiring stores once it exists, and the run goroutine starts only after the store. `speculativePrewarm(messageID)` is a no-op on an empty id or a stopped wiring and otherwise spawns `go w.prewarmWorker(w.endCtx, messageID)` — one fast dispatch on the rank worker, then return. `endCtx` is the workers' deadline scope (cancelled at session end), so a prewarm the run never gets to consume is cut at the source.
3. **The fences are untouched.** The prewarm fills the cache; it emits no speech event, schedules nothing, and moves no fence. The commit's own `speech.requested`/`ready` and the fence advance happen exactly as before — the prewarm only decides whether the commit's `GetOrGenerate` finds the bytes already in flight or in the cache. A Clef verdict that picks the runner-up leaves the prewarmed top-1 key unconsumed; it is counted by the prewarm's own `wasted`/hit bookkeeping (FR-11's accounting), which is the honest shape for a speculative byte that never committed.
4. **The production margin in the multi-box E2E.** `perchar_live_test.go` and `catchup_live_helpers_test.go` set `DecisionOptions.Margin` to `0` (matching `cmd/game-narrator/main.go`): a confident local match commits on the local evidence and skips Clef, while an abstained or fuzzy-below-bar ranking still consults it. `dolphin_live_test.go` deliberately keeps `dolphinClefMargin = 0.99` because that test's acceptance is a Clef request on the opening line — it is the test that *proves* the round trip, so it must not skip it.

## Tradeoffs

- **One speculative synthesis per ambiguous line.** When the verdict narrows away from the top-1, the prewarmed line's bytes are spent-but-unconsumed and count as `wasted`. That is the cost of the overlap, and it is bounded (one synthesis, the same key a commit would use) and the documented FR-11 degradation — the budget the byte quota and the provider limiter already own.
- **The hook fires even when the prewarm is a no-op.** A process with no speech wiring (or a run with no approved voice for the speaker) still fires the hook; `speculativePrewarm` returns without spawning. The hook is the seam, the no-op is the caller's policy.
- **The E2E no longer exercises the per-line Clef path by default.** At `Margin: 0` the multi-box lines commit on the local evidence, so those tests no longer assert a Clef round trip per line. That is the intended production shape (the per-character test asserts voices, the catch-up test asserts the batch — neither asserts the decision stage). The per-line Clef path stays covered by `dolphin_live_test.go` and the runtime's `TestDecisionAdjudicatesAmbiguousCommit` (which uses the `Margin: 1.0` lever).

## Validation

- **Unit** (`internal/pipeline/onadjudicating_test.go`):
  - `TestPipelineOnAdjudicatingHookFiresBeforeDecide` — the corpus replay with the adjudication on at a margin no accepted ranking can clear (`AdjudicateMargin 1.0`, the same lever the runtime's decision test uses). Asserts `Decider.Decide` was called, the hook fired **before** the first `Decide` (captured at `Decide`'s entry), and the hook's message id equals the decision request's `Candidates[0].MessageID` for every paired call (one hook per `Decide`, same top candidate).
  - `TestPipelineOnAdjudicatingNotFiredWithoutAdjudication` — the gate: the Decider is wired but the adjudication is off, so neither `Decide` nor the hook runs on a confident local match.
- **Regressions.** `go test -race ./internal/pipeline/... ./internal/runtime/... ./internal/e2e/...` (without `GN_GATE`): the pipeline and runtime suites pass; the e2e package's live tests self-skip (NOT RUN — no Dolphin gate / game image / provider env) and the package builds and vets clean, so the margin edits compile and the live acceptance is unchanged on the shapes it asserts.

## Consequences and reversal

- **Consequences.** A confident local match in the multi-box E2E commits without a Clef round trip (production parity), and an ambiguous line's top candidate is synthesised in the background while Clef is out, so the commit's TTS is a cache hit or a joined generation instead of a serial round trip. The pipeline gains one additive, nil-safe seam; the runtime gains one atomic pointer and a fast dispatch. The commitment policy, the speech fences, the singleflighted cache and FR-11's successor prewarm are unchanged in shape.
- **Reversal.** Delete the `OnAdjudicating` field, the rank-worker call, the `specSpeech` atomic and `speculativePrewarm`, and the E2E margin reverts to `dolphinClefMargin` — the pipeline, the session and the tests fall back to the serial round trip with no schema, no cache-key and no fence change. The seam is additive: removing it restores the pre-change behaviour exactly.
