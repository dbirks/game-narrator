# ADR-0111: The Health screen — tile grid over the status rollup, the signal/preview tile, and the /diagnostics rename

Date: 2026-10-20 (amended the same day for the run-3715836 visual review)
Status: accepted
Owners: p1-health
Related requirements/tests: docs/design/plum-peach README.md 2i ("Health"), product-notes.md UX-07 ("One live status stream feeds the status bar") and UX-11 ("HDMI signal and active-picture preview"), docs/spec/09 ("Routes and page requirements"), ADR-0093 §4 ("Diagnostics becomes Health (`/diagnostics` → `/health`)"), ADR-0100 (status snapshot + stream), ADR-0106 (the G17 telemetry surface: the sparkline's considered-but-deferred second source), ADR-0110 (GET /api/v1/capture/signal and the session-frame preview)

## Context

ADR-0093 renames Diagnostics to Health (`/diagnostics` → `/health`, old path redirects) and re-presents it as "a tile grid of subsystem statuses": a 3×2 grid (capture, OCR, decision model, voice (TTS), agent model, storage), each tile a mono label, a status tag (`--peach` ok, `--coral` slow/fail), a one-line detail and a 12-bar dithered sparkline; non-ok tiles also surface in the global status bar (UX-07). The screen spec (README 2i) adds a page tab row — line traces · setup runs · health · logs — with the existing diagnostics content (readiness checks, logs, …) preserved, and UX-11 requires the Health surface to show **HDMI signal present** and an **active-picture** preview so a dead cable or sleeping converter is visible immediately.

The backend seams already exist and are the only sources this screen reads:

- `GET /api/v1/status` + `/api/v1/status/stream` (ADR-0100) carry the six-tile health rollup — cached answers only, canonical component order, the levels ok/slow/fail/unknown — and the server-rendered status string whose tail names every non-ok tile. The status bar already renders it on every page (Phase 0); nothing about the bar changes.
- `GET /api/v1/capture/signal` + `/api/v1/capture/preview` (ADR-0110) carry the signal/picture halves for the capture tile: `signal` (source aliveness; a card delivering black is signal present) and `picture.active` (the non-black "is the picture there" judgment), with the throttled 640 px JPEG preview.
- The pre-existing diagnostics endpoints (host vitals, the model-role probes, the voice registry, the speaker test, the log tail, the readiness checks, the job queue) keep their contracts.

No backend change is needed for the screen: the acceptance's "fixture health report containing one non-ok tile" is a fixture feed (the spec scripts the status endpoints with a canonical snapshot, AGENTS.md rule 3 class (a) — synthetic stub, labelled as such), because a healthy dev box has no non-ok tile to show for real.

## Decision

### 1. Route and file rename (ADR-0093 §4)

`web/src/pages/Diagnostics.tsx` becomes `web/src/pages/Health.tsx` (the section components move to `web/src/pages/health/`); `App.tsx` mounts `HealthPage` at `/health` (still a public route, outside the auth guard — readiness and build info must be inspectable before an account exists, ADR-0016 §3) and `/diagnostics` becomes `<Navigate to="/health" replace />`. `web/e2e/diagnostics.spec.ts` becomes `web/e2e/health.spec.ts` and the two sibling specs that visit the old route (route-coverage, a11y) move to `/health`; the NotFound and Setup-wizard cross-links point at `/health`. This item's ADR-backed IA change (0093 §4) is the only reason any pre-existing selector is touched.

### 2. The 3×2 tile grid reads the one status stream

The grid renders `snapshot.health.components` from the app-root `LiveStatusProvider` feed — the same single subscription that powers the status bar (UX-07's "one stream per page"), so the tiles and the bar cannot disagree. Tile vocabulary is the canonical order (capture, ocr, decision, tts, agent, storage). The tag: ok is the peach fill (the design's "selected/current" chip), slow/fail is the error language (coral border, ink text — text stays ink so the small mono label holds WCAG 1.4.3, the border carries the hot accent), unknown is the neutral chip; the one-line detail is the rollup's own `detail` (the evidence, or the fact that there is none). A non-ok tile is never restyled into a fake OK by the client; "unknown" is its own word, exactly as the rollup means it.

**Layout and labels (run-3715836 review fixes 1 and 2).** The grid spans the page's content width — a 3×2 grid of the six large tiles at the desktop width (three columns), two columns at 1024, one at 390 — not a narrow column; the preserved sections run full-width under it (two columns at the desktop width, see §4). The tile labels are the design's full names (capture card · OCR · decision model · voice (TTS) · agent model · storage) and wrap rather than truncate, so the word the status bar uses is the word the tile shows.

**The 12-bar sparkline (run-3715836 review fix 3; supersedes the original "appended on every feed frame" cadence).** The original shape — appending the level per delivered feed frame — left every window at the floor on a healthy box, because the feed pushes only on change (ADR-0100's "push on change" rule) and an idle box's frames never arrive: the review's "empty dashes". The amended shape keeps the ADR's source and encoding but changes the cadence: the page runs its own fixed one-second sampler that records the tile's current level from the one stream's newest frame (a ref read inside the interval — the page's clock, not the feed's), and the twelve-bar window is the tile's last twelve seconds. The bar heights encode the levels (ok 100 / slow 55 / fail 25 / unknown 0) on a FIXED scale top of 100 — the kit `Sparkline` gained a `max` prop for this, because scaling to the window's own max renders a uniform fail window as a full bar and loses the level the ADR pins — so the floor (2 px) is now rendered only by a tile nobody probed (unknown, or no frame yet), which is the honest empty state the review asked for, and only that. The G17 metrics snapshot (ADR-0106, `GET /api/v1/dev/metrics`' per-component latency histograms) remains the considered-but-deferred second source: it is developer-tier only (the health page serves viewer tier) and ADR-0106's own decision keeps the two surfaces separate; a future "latency shape" mode would read it when the principal's role admits it and fall back to this level window when not. In-memory, per visit, no new endpoint, no new network read — the sampler touches no route.

### 3. The capture tile is the UX-11 tile

The capture tile alone carries the signal/preview block, because it is the tile the requirement names:

- `GET /api/v1/capture/signal` (operator; 401/403 render the page's own sign-in/role hint, 409 `capture-signal-unavailable` renders the operator action in the detail, 503 the "no capture layer" note) is polled at 2.5 s — inside the shared 500 ms one-shot throttle budget with margin, aborted on unmount and on tab leave — and renders the two status words with stable testids: `health-tile-capture-signal` is "signal present" / "no signal" from `signal`, `health-tile-capture-picture` is "active picture" / "no active picture" from `picture.active` (the UX-11 wording, asserted by testid).
- `GET /api/v1/capture/preview` feeds the tile's picture (a real JPEG from the production encoder, object URLs revoked on replace/unmount, 2.5 s cadence, the same throttle). The preview is the only `<img>` on the page; it shows the session's newest frame while a session runs (ADR-0110 §2) and the one-shot grab otherwise.
- The rollup's capture level (session-derived: the fps against the target) still drives the tile's tag; the signal block is the evidence row under it. The picture word follows the tracker's own `ActiveArea` judgment (the bar-framed window the game's textbox lives in): a session on a letterboxed game screen says "signal present · active picture"; a card delivering a full-frame pattern (the e2e seam's testsrc2) is honestly "signal present · no active picture" while its JPEG preview still shows the picture — and a black card separates from "no signal" on the signal word alone. The tracker's positive judgment on a real (bordered) frame is pinned by `TestCaptureSignalOneShotBorderedFrame`; the tile's rendering of both words by the e2e's labelled scripted-stub test (AGENTS.md rule 3a).

The black/static half of UX-11's acceptance is exercised with a scripted signal fixture in the spec (the fake dongle's testsrc2 pipe is the changing-feed half, the real production path); the real-card run stays NOT RUN until the hardware is attached, per ADR-0110's own boundary.

### 4. The tab row and the page's summary title

The page's title (the run-3715836 review fix 4; README 2i's 36/600 page title, Fredoka 36 px) is the rollup's own summary, rendered from the one stream's counts only — never a re-derived level: the mock's `Everything's mostly fine` (to the letter) when every tile is ok, `N need attention` when N tiles are slow or fail (the rollup's non-ok tail, the same word the bar carries; `1 needs attention` in the singular), with the unprobed count appended when the box has unknowns (`2 need attention · 3 unprobed`), and `N unprobed` for a box nobody has probed yet (its honest word, never a restyled "all fine"). Before the one stream has delivered a frame — the anonymous visit's 401 — the title is the page's own name, `Health`, which the pre-rollup asserts of the anonymous and redirect walks still hold. The four-tab row the spec names — line traces · setup runs · **health** · logs — sits to the title's right on one line (it wraps under the title on a phone) and is rendered with the kit `Segmented` (the Radix tablist contract: role=tablist, arrow-key motion, aria-selected). **health** is the default and holds the grid plus the preserved sections (host vitals, video input, the model-role probes, the voice registry, the speaker test, the readiness checks, the job queue) in a full-width two-column grid at the desktop width (the run-3715836 review fix 5: they no longer sit in the narrow 34 rem column the pre-fix page wrapped them in; their data-testids are unchanged). **logs** holds the preserved system-log tail. **setup runs** lists the active onboarding runs from the same one status feed (`snapshot.setup_runs`: state, stage, voiced/total, elapsed) — real data from the one stream, with a dashed empty state and a Library link when none is active. **line traces** is the one tab the API cannot feed a history: per-line inspection lives on the Traces screen (ADR-0093: Traces is named for "per-line traces of the live run"), so the tab shows the active session's line activity from the status snapshot when one runs and, with no session, an honest dashed empty state linking to `/traces` — never a fabricated list. No tab persists across visits (the UX-08 persistence rule is for the Library/Cast view toggles only).

### 5. E2E home

`web/e2e/health.spec.ts` runs on its own `health` webServer and project (the packaged binary with `GAME_NARRATOR_CAPTURE_FAKE` — the labelled-synthetic dongle fed by the real FFmpeg testsrc2 pipe, on its own port and data directory), because UX-11's acceptance needs a signal/preview the production pipeline can answer: the spec claims that throwaway appliance as admin, persists the device selection, and asserts the tile grid, the signal/preview words and the picture, the tabs, the preserved sections' honest signed-out/signed-in states, the `/diagnostics` redirect, the non-ok-tile fixture (scripted status endpoints) on `/health` and on another page's status bar, and the three-width screenshot + axe + no-horizontal-scroll pass. It gets its own server rather than sharing the `capture` walk's: the appliance claim is once per appliance (ADR-0016 §7) and the two walks would contest the same claim and device selection. The dev-server project ignores the spec (its server wires no capture layer, so the signal assertions would have nothing real to assert against).

## Alternatives considered

1. **A dedicated health endpoint.** Rejected: the rollup already exists in the status snapshot (ADR-0100) and a second read would be a second source the bar and the tiles could disagree about; the requirement is that non-ok tiles surface everywhere from one stream.
2. **Polling the signal route into the status stream (backend change).** Rejected for this item: ADR-0110 §6 defers the signal state to the live stream as a follow-up; the screen's acceptance needs the tile's own block, and a backend change to the canonical string is a protocol change with its own ADR and contract tests, out of this item's file ownership.
3. **Rendering the tiles from per-component reads (doctor run, readiness, …) on the page.** Rejected: that is the pre-redesign page; the design's grid is the rollup, and a page that re-derives the levels client-side would invent a second vocabulary the bar does not share.
4. **Making line traces / setup runs into navigation links instead of tabs.** Rejected: the screen spec names them as tabs; real-content tabs (setup runs from the one stream; line traces' honest session-or-pointer state) respect the spec without fabricating a history the API does not have.

## Consequences

- `/health` is the public diagnostics surface; `/diagnostics` keeps working as a redirect (muscle memory, ADR-0093's tradeoff).
- The Health page's only new network cost is the 2.5 s signal/preview pair, bounded by the shared one-shot throttle and stopped when the tab is not on screen; every other read is the preserved set or the one status stream. The sparkline's sampler is in-page only (one interval, a ref read): no route, no second subscription.
- The sparkline window is per-visit memory: a reload starts at the floor and fills over the first twelve seconds. Accepted — the design calls it a pulse, and a persisted health history is a feature, not a texture.
- E2E: one more packaged-binary project against the existing capture server; the scripted-status assertions are labelled synthetic-stub (AGENTS.md rule 3) and the signal/preview assertions are the real production pipeline on the synthetic seam (ADR-0078's labelled-honesty rule).

## Validation

- Unit: `web/src/pages/Health.test.tsx` — the fixture feed (one non-ok tile) drives the grid: the summary title (the mock's `2 need attention`), the coral tag, the one-line detail, the 12-bar sparkline filled from the one stream on a fast tick (ok → full bar, fail → the quarter bar, an unprobed tile → the floor only), the `healthSummaryText` contract, the bar string carrying the tile name, the tabs, and the capture tile's signal/picture words from scripted signal answers.
- E2E: `web/e2e/health.spec.ts` (plan.md item 8's acceptance) — the `/diagnostics` redirect; the 3×2 grid over the real stream on a fresh appliance (the full-wrap labels, the `5 unprobed` title, the storage tile's sparkline filled from the one stream and the unprobed tile's honest floor); the signal present and the real JPEG preview, with the picture word's honest full-frame answer ("no active picture" — the tracker's `ActiveArea` only finds the game's bar-framed window) on the labelled synthetic seam; the picture word's positive and black halves from the scripted signal fixtures (the tracker's positive path is pinned by the Go test `TestCaptureSignalOneShotBorderedFrame`); the non-ok tile's coral tag and the status bar on another page from the scripted non-ok snapshot (its `2 need attention` title and the level-filled sparklines, ok 20 / slow 11 / fail 5); the preserved readiness/logs/sections full-width under the grid; screenshots + axe at 1440/1024/390 with no horizontal scroll at 390.
- OpenAPI/contract: untouched (no backend change; the kit `Sparkline`'s `max` prop is additive and the `/dev/kit` gallery exhibits it).

## Reversal plan

Restore `Diagnostics.tsx`/`diagnostics.spec.ts`, the original `/diagnostics` mount and the `/health` redirect in `App.tsx`, the two cross-links, and the two sibling specs' old routes; delete `web/src/pages/health/` and the ADR. Nothing here touches persistence, the protocol or the store.
