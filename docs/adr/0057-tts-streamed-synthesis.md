# ADR-0057: TTS streamed synthesis — an optional, capability-negotiated streaming wire with a real mid-synthesis cancel

Date: 2026-10-18
Status: accepted
Owners: agent worker
Related requirements/tests: docs/spec/07 ("Audio scheduler", "Input UtteranceReady … voice ID, priority"; "streaming TTS, fenced at every chunk boundary"), docs/spec/12 ("TTS partly streams before cancellation": after cancellation the source stops receiving `Next` calls and no late audio plays; "Zero stale audio starts"; "provider failure injection"), docs/spec/16 M7 ("no silent voice mismatch or stale speech"), ADR-0023 (speech cache and scheduler — the scheduler is the single owner of device-level playback events), ADR-0037 (scenario fault injection — the `endpoint_down` fault and "blocked ≠ pass"), docs/status/blocked.md (the GN-T047 row this ADR clears), `docs/test-plan/scenario-catalog.md` row GN-T047 ("TTS stream partial/cancel … no stale audio, temporary file cleanup")

## Context and constraints

The TTS provider contract (`internal/providers/tts`) is atomic: `Generate` issues one request and returns one fully validated WAV or a classified error. That is honest and simple, but it leaves one M7 failure-injection scenario unrunnable — GN-T047 "TTS stream partial/cancel". The scenario's fault is the TTS endpoint dying while an utterance is still being synthesised. Against an atomic contract there is no stream to interrupt: the request either returns a complete WAV or it errors, so "the audio stops, no stale audio starts, and the temporary file is cleaned up mid-utterance" would assert a property the product does not have. ADR-0037's rule ("blocked ≠ pass", AGENTS.md "No simulation theater") therefore holds GN-T047 `status: blocked` and the scenario is reported `BLOCKED`, never passed.

The unblock steps ADR-0037 drafted were: give the contract a streamed/cancellable synthesis endpoint (or add a synthesis-failed-mid-playback phase to the session lifecycle), express the fault as a `tts`-role `endpoint_down` window, and flip the scenario off `blocked`.

The deployment was probed before deciding. `POST /audio/speech` with `"stream": true` (model `qwen3-tts-base`) answers `200` with `Content-Type: text/event-stream; charset=utf-8`, chunked, no `Content-Length`, and no `X-Request-Id` (the client mints the request id and records its source). The frames are `event: speech.audio.delta` carrying a JSON `data` payload `{"type":"speech.audio.delta","audio":"<base64 wav>","response_format":"wav"}`, terminated by `event: speech.audio.done` with a `usage` object. The first delta is the 44-byte RIFF/WAVE header with the RIFF size and the `data` chunk length carrying the `0xFFFFFFFF` streaming markers (the RIFF convention for a file that arrives in chunks); the following deltas are raw PCM. Decoded and concatenated (with the two length fields patched to the bytes actually received), the deltas form one complete, valid WAV. First-byte latency measured ~112–119 ms against ~717 ms for the atomic path, and the connection can be closed mid-stream (the endpoint dies) with the client seeing the read end before the terminal event. `qwen3-tts-voicedesign` 400s on the synthesis route — it is a design-only checkpoint — so the streaming wire is exercised on the Base (voice-clone) checkpoint, which is the one the runtime speaks with.

The hard constraints that shape the design:

1. **The atomic path stays the default and the fallback.** The scheduler already prefers the buffered WAV (`UtteranceReady.WAV`) and treats a streaming source as the secondary path fenced at every chunk boundary. A deployment that refuses the stream flag, or that ignores it and answers the atomic wire, must keep working with no caller change. Streaming is a capability the deployment negotiates, never an assumption.
2. **A mid-stream failure is terminal and the partial is never returned.** The contract is "one complete validated WAV or a classified error". Whatever bytes had arrived when the stream died are the progress a failure report names — not audio to play.
3. **Cancellation mid-synthesis must be real.** The pipeline's fence moves on every new commit. Today a fence that moves while a line is still being synthesised cannot stop that work — the atomic `Generate` runs to its own deadline and the result is fenced only when it arrives. With a streaming wire the fence can cancel the read at the source: the partial is discarded, the utterance ends failed, and the phase fence keeps it from starting later.
4. **No simulation theater.** The scenario must run the real client over the real wire shape; the fault must land at the wire (the connection dropping mid-stream), not be faked in a wrapper before the request.

## Decision

Add an optional streaming synthesis path to the TTS contract, capability-negotiated, with cancellation that stops the read and discards the partial. The atomic `Generate` is untouched and remains the default; nothing in the runtime changes unless the client it holds implements the streaming seam.

### Contract (`internal/providers/tts/stream.go`)

- `Client.OpenStream(ctx, req) (*Stream, error)` issues the synthesis request with `stream: true` and returns the in-flight stream on a `200`. A `400` that names the stream flag is recorded as the negotiated capability (`ErrStreamUnsupported`, `KindUnsupportedCapability`, non-retryable) so the caller falls back to the atomic path instead of re-asking. A `200` that is not `text/event-stream` (the deployment ignored the flag) is wrapped as a one-shot stream and recorded as "ignored" — the deployment's actual behaviour is the negotiation, never an assumption.
- `Stream.Next() ([]byte, error)` delivers the next decoded audio delta (the base64 `audio` payload, decoded) and `io.EOF` at the terminal `speech.audio.done` event. A mid-stream failure is sticky: every later `Next` returns the same classified error. The read error is classified — a caller cancellation is `KindCancelled`, a deadline is `KindTimeout`, and a connection that ends before the terminal event is the endpoint dying mid-synthesis (`KindUnavailable`, retryable). Each carries the decoded byte count already delivered.
- `Stream.BytesRead()`, `Stream.RequestID()`, `Stream.RequestIDSource()`, and `Stream.Close()` expose progress, the effective request id (the deployment's answer header when it carries one, else the client-minted `X-Request-Id`) and its source, and release the body (safe to call more than once).
- `Client.GenerateStream(ctx, req) (Audio, error)` is the one-shot form callers actually use: it opens the stream, drains it, patches the streaming placeholder header, and returns the same provenance record `Generate` does — one complete validated WAV, or a classified error. The partial is never returned. When the deployment has negotiated itself as non-streaming it serves the call with the atomic `Generate` without re-asking; a deployment that ignores the flag is transparent (its `200 audio/wav` answer is wrapped as a one-shot stream).
- `normalizeAssembledWAV` repairs the measured wire's placeholder header: the first delta's RIFF size and `data` chunk length carry the `0xFFFFFFFF` streaming markers, and the assembled file is not valid until those fields name the bytes actually received. A file whose lengths already name it (a deployment that ships final lengths, or a one-shot body wrapped as a single chunk) passes through byte-identical; a buffer that is not a WAVE is left for the validator to name. Only a `data` chunk declared to run to the end of the file is touched — anything else is a file the validator must judge, not a placeholder to paper over.
- `IsCleanEnd(err)` distinguishes the stream's clean terminal (the `done` event) from a mid-stream failure, whose error wraps the read error (which is `io.EOF` when the connection simply closed) through its cause. Callers must not test failures with `errors.Is(err, io.EOF)`.

### Runtime (`internal/runtime/speech.go`)

The runtime's fence now cancels an in-flight synthesis at the source. `speechWiring` holds `genCancel map[int64]*synthSlot` — the cancellable context of a synthesis still in flight, keyed by the utterance's generation. The `speak` worker wraps the deadline scope in a per-utterance cancellable context and registers it; a `defer` deregisters it and cancels it when the synthesis settles. `fenceAndCancel` (called on every new commit) cancels the registered slots of every stale generation before it cancels the scheduler, so the stream's partial is discarded and the utterance ends failed instead of starting later. `resolvedVoice.generate` uses the streaming seam when the client implements it (the real `tts.Client` does; the test fakes stay atomic) for the registered-voice path; the inline-reference path stays on the atomic `GenerateWithReference` contract. A fence that moves mid-synthesis therefore classifies as a cancellation (the synthesis context is cancelled), not a wire fault.

### Scenario harness (`internal/scenario`)

The fake TTS gateway speaks the real streaming wire: it answers `stream: true` requests with the measured SSE shape (the `speech.audio.delta` frames carrying a base64 WAV, a `speech.audio.done` terminal), and splits the tone WAV into deltas the way the deployment cuts its frames. The `endpoint_down` fault for the `tts` role now rides the capture clock the harness stamps on the gateway before each call — the synthesis payload carries no capture clock — and applies at the wire: a streaming request stamped inside the window gets its SSE connection dropped after half the audio, with no terminal event. That is the endpoint death the fault names, and the real client classifies the mid-stream EOF as the endpoint-down failure.

The run's playback half is now real, not event-only: a generation-fenced `speech.Scheduler` over a `filesink` under a per-run temp dir. The scheduler's publisher is a discarding stub because the sidecar session is the event recorder of record for the merged timeline (duplicating the scheduler's playback events would double-count every start), and the scheduler's fence is the session's commit generation — the same rule the runtime's fence applies (docs/spec/01 invariant 2). Every commit advances that fence and cancels older generations at the source. A new implicit check, `audio_evidence_clean`, is appended to every TTS-scenario report like `replay_not_degraded` (not authorable): the sink's directory must carry exactly one evidence WAV per started utterance and no temporary file. That is the "no stale audio starts" and "temporary file cleanup" the catalog row asks for, asserted against the sink's own directory rather than the event log alone.

The GN-T047 scenario is flipped off `status: blocked`. Its fault window covers the second line's commit (the matcher commits the second page at capture 2200 ms; the window is `[2000, 2400)`), while the first line commits at capture 1500 ms and synthesises untouched. Its assertions run: `fault_count endpoint_down 1`, `no_stale_speech demo-page-2`, `no_duplicate_speech demo-page-2`, `no_voice_substitution synthetic-narrator`.

The `no_voice_substitution` evaluator now accepts a failed utterance with a reason as a terminal outcome ("silence with a reason"): the requested voice's utterance ended, the error names the cause, and the voice named is the requested one. The `voice_missing` case (the failure names the missing voice) still lands in the same bucket. A failed utterance with no reason is still not a terminal outcome.

## Options considered

- **Add a synthesis-failed-mid-playback phase to the session speech lifecycle instead.** The session's `speechAdvance` table already has a terminal `PhaseFailed` reachable from `PhaseStarted`, and a mid-synthesis failure ends the utterance `failed` through the existing `SpeechFailed` message — no new phase is needed. The blocking gap was in the provider contract (no stream to interrupt), not the session. Adding a phase would have moved the fence but left the atomic `Generate` running to its own deadline, so the cancel would still not have been at the source.
- **Make the runtime cancel the scheduler's queued/active work only, and leave synthesis atomic.** That is the status quo and is why GN-T047 was blocked: the fence could not stop a synthesis that had not finished, so a stale or cancelled line could still complete and start. The streaming seam plus the `genCancel` slots make the mid-synthesis cancel real.
- **Return the partial audio and let the caller decide.** Rejected: the contract is "one complete validated WAV or an error". A partial that is not validated is not speech the session may claim to have heard; the byte count is surfaced in the error for the report, and the partial is discarded.
- **Assume every deployment streams and remove the atomic fallback.** Rejected: the deployment's answer is the negotiation. A `400` naming the flag, or a `200` that ignores it, must keep the atomic path working with no caller change, and the capability is recorded per client so the fallback is not re-requested.

## Tradeoffs

- The streaming path is one more wire to keep honest: the SSE frame shape, the base64 delta, the placeholder header, and the terminal event are all things a deployment can change. The capability negotiation (record `unsupported`/`ignored`/`served` once, per client) bounds the blast radius — a deployment that changes the wire falls back to the atomic path rather than failing, and the live test below re-proves the wire against the real checkpoint.
- `GenerateStream` drains the whole stream in the caller's goroutine (the cache's generation function), so a very long utterance holds the worker for its full synthesis. The scheduler's streaming-source path (`UtteranceReady.Source`, fenced at every chunk boundary) is the shape that would hand the stream to the loop, and the contract already accepts it; wiring it is a follow-up, not part of this unblock, because the runtime today synthesises to a buffered WAV before the scheduler's fence-checked start.
- The scenario harness now runs a real scheduler and filesink, so a scenario run is a little heavier and writes a temp dir per run. The directory is kept as the run's audio evidence (the report links it) and the implicit check reads it; the cost is bounded by the scenario's utterance count.

## Verification

- `go test -race -count=1 ./internal/providers/tts/` — the streaming unit tests (`TestGenerateStreamHappyPath`, `TestGenerateStreamMidStreamDrop`, `TestStreamCancelMidStream`, `TestGenerateStreamCancelDiscardsPartial`, `TestGenerateStreamServerIgnoresFlag`, `TestGenerateStreamUnsupportedFallback`, `TestStreamMalformedFrame`, `TestStreamUnknownEventsAreIgnored`, `TestStreamCloseIdempotent`, `TestNormalizeAssembledWAV`, `TestGenerateStreamStreamingPlaceholderHeader`) plus the live tests.
- `TestLiveStreamGenerateViaGateway` (NOT RUN without the gateway env; run here) proves the wire against the real `qwen3-tts-base` checkpoint: one complete WAV assembled from the deltas (the placeholder header patched and validated), and a genuine mid-stream cancel — the caller's context is cancelled after the first delivered delta, the partial is discarded, and the failure classifies as a cancellation. The log carries the effective request id and the bytes read before the cancel (measured: `deltas_before_cancel=2`, `bytes_read_before_cancel=3884`, `err=cancelled: … after 3884 audio byte(s)`).
- `go test -race -count=1 ./internal/scenario/` — `TestScenarios` runs every scenario; GN-T047 now loads, runs over the real streaming wire, and passes all four of its assertions plus the implicit `audio_evidence_clean`. The fault fires exactly once mid-stream; no utterance for `demo-page-2` ever starts; the failed utterance ends with the requested voice and the reason; the sink dir carries one evidence WAV for the one started utterance and no temporary file. `TestBlockedScenariosAreReportedNotPassed` keeps the "blocked ≠ pass" rule exercised on a synthetic blocked YAML now that the register holds no synthetic rows.
- `go test -race -count=1 ./internal/runtime/` — the runtime's fence-cancel tests pass with the `genCancel` slots in place; a fence that moves mid-synthesis cancels the synthesis context (the `TestFaultTTSEndpointDownViaWrapper` and the scenario's `endpoint_down` path exercise the same wire shape).
- Probe evidence (measured, no secrets): `stream: true` → `200 text/event-stream; charset=utf-8`, chunked, no `X-Request-Id`; first delta a 44-byte RIFF header with `0xFFFFFFFF` size and `data` length; following deltas raw PCM; `speech.audio.done` terminal with `usage`; first-byte ~112–119 ms vs ~717 ms atomic.

## Consequences

- The GN-T047 row leaves the BLOCKED register (docs/status/blocked.md, moved to Cleared 2026-10-18 with this evidence) and the catalog's TTS stream partial/cancel row is covered by a runnable scenario.
- The TTS contract now has two synthesis paths with one provenance shape; callers that do not need streaming (the test fakes, the reference path) are unchanged, and a deployment that does not stream is unchanged (the fallback is transparent).
- The runtime's mid-synthesis cancel is real: a new commit stops a line still being synthesised at the source, so "zero stale audio starts" now holds across the synthesis, not just from the scheduler's start onward.
- The M7 fault-injection set (docs/spec/16) is complete over the synthetic clip: every fault kind in the minimum-quality policy has a runnable scenario, and the one that was blocked on the provider contract is no longer blocked.

## Amendment (2026-10-18, same day — cancellation is terminal before delivery)

Measured defect found while stabilizing the test suite: `Stream.Next` surfaced the caller's cancellation only when the next *wire* read failed. Deltas that had already buffered (the fake SSE server bursts all frames before the test cancels) were still delivered: a `Next` after `cancel()` returned a chunk with a nil error — the contract ("cancellation … stops the read and surfaces `KindCancelled` with the progress") violated. The failure mode was worse than the assertion: the test failed at the assertion, and the deferred `httptest.Server.Close` then deadlocked behind the handler's held terminal frame (goroutine dump: `Close` in `WaitGroup.Wait`, handler in `chan receive`). Two fixes:

- **Product** (`internal/providers/tts/stream.go`): `Next` checks the request context before every delivery — cancellation and deadline expiry are terminal even with deltas buffered; the buffered bytes count toward the progress the error names. `TestStreamCancelMidStream` fails cleanly in ~4 ms without the check (the regression guard) and passes 50 consecutive runs under single-core load (`taskset -c 0 -race -count=50`) with it.
- **Test harness** (`internal/providers/tts/stream_test.go`): the SSE handler's held terminal frame also releases on the request context's `Done`, so a cancelled or gone client can never wedge `Server.Close` again.

## Rollback / migration path

The change is additive and capability-negotiated. To roll back: delete `internal/providers/tts/stream.go` (and `live_stream_test.go`, `stream_test.go`), remove the `streamingSynthesis` seam and the `genCancel` slots from `internal/runtime/speech.go` (restoring the direct `Generate` call and the scheduler-only `fenceCancel`), remove the SSE branch and the `endpoint_down`-at-the-wire behaviour from the scenario gateway, and restore the GN-T047 YAML's `status: blocked` + reason. The atomic `Generate` path is untouched throughout, so a rollback restores the exact pre-ADR behaviour with no data migration; the `audio_evidence_clean` implicit check and the scheduler/filesink in the harness would be removed with the scenario's TTS playback half.
