# Gap audit — what is still missing before real hardware and real users

2026-10-19, from the committed tree at `3625f55` (the acceptance-report tree,
re-issued 3afe9a4). Method: every `docs/spec/*` section was read in full and
each requirement checked against the code with `grep`/`sed`; claims below
cite `file:line` evidence. Status classes:

- **NOT IMPLEMENTED** — the spec asks for it, no code path exists (or the
  product surface refuses it by design, e.g. 501).
- **UNTESTED** — code exists, but no test (synthetic or live) exercises the
  spec'd behaviour.
- **STUB-ONLY** — tested only with synthetic stubs where the spec asks for the
  real thing.
- **UNREACHABLE** — implemented in the backend but not reachable from the UI
  (or reachable only by editing an env file and restarting the service).

Severity: **blocks** = a real user cannot use the product mode the spec's
headline journey describes; **degrades** = the mode works but a named spec
behaviour is absent/unproven; **polish** = named detail, low user impact.

The in-flight managed replay-clip store (acceptance Gap 3, `internal/clips` +
`internal/api/clips.go`, uncommitted at this audit's tree) is deliberately
excluded from the findings below — it is tracked there and lands with its ADR.

## What the README promises that does not exist

The README's quickstart/gate/CLI claims were checked line by line against the
tree and all hold: every `make` target it lists exists (`Makefile:30-363`), the
CLI subcommands match (`cmd/game-narrator/main.go:297-315`), `doctor` reports
`OK/DEGRADED/BLOCKED/NOT CONFIGURED/FAIL` (`internal/doctor/doctor.go:14-45`),
the `.env.example` role placeholders exist, and the cosign/SBOM verification
commands match `docs/release.md` / `docs/manuals/17`. The promises that fall
short of the *product* (not the README's literal wording) are:

- "speech out to a USB sound device" (README intro) — selectable only through
  an env var with no device discovery, no verification tone and no UI
  (G5); on the UNO Q it is also not yet proven end-to-end (G1, blocked.md).
- "the same pipeline also runs against Dolphin on a development host" — true
  for the dev bridge, but the production *capture* leg of that pipeline is
  501 in the session runtime (G1).
- "choose conservative/predictive playback, pause/mute" (charter journey the
  README points users to) — pause and narrated-class selection are not exposed
  (G7).
- Nothing in the README promises updates/notifications, restore-from-UI or
  per-character-voice *proof*, so G3/G6/G11 are spec gaps rather than
  README-broken promises.

## Top 10 (ranked)

Ranked by impact on the two questions in the task title — real hardware and
real users — with effort noted. Rank 1-4 are the "blocks" set; 5-10 are the
highest-value "degrades" for a first human operator.

1. **G1 — Wire the physical capture session (blocks).** `POST /sessions`
   with `frame_source.kind=v4l2` answers 501 (`internal/runtime/source.go:208-209`);
   the primary product mode (GameCube → HDMI splitter → UVC → UNO Q, spec 00)
   cannot run a session on the hardware the release targets, even though the
   V4L2 source component (`internal/capture/ffmpegpipe/ffmpegpipe.go:163`) and
   the on-device smoke exist. Unit of work: wire `ffmpegpipe.V4L2` (device
   path + input format from config/selection) into `buildFrameSource` behind
   the same allowlist/501 discipline as dolphin, with the doctor/hwsmoke
   freshness and dropped-frame checks, a session test against a recorded
   V4L2 fixture, and the Play page source option; acceptance = on-device
   `make test-hardware` at 0 NOT RUN and a sustained run with
   `--source capture`.
2. **G2 — Device enumeration/selection/preview surface (blocks).** No
   `capture/devices|probe|preview` API and no UI (spec 08 minimum set;
   FR-01). Unit of work: the three spec-08 routes (device list with stable
   IDs, mode negotiation, throttled authenticated preview + screenshot), a
   Setup/Settings capture section driving them, Playwright assertions on
   visible device state, and the spec-10 test-OCR hook reusing the existing
   regions-preview engine; acceptance = a user on the UNO Q can pick the
   dongle, see its frames in the browser and run the capture test without
   touching env files.
3. **G3 — Prove per-character voices in play (blocks the product's reason to
   exist).** The resolution path is wired (`internal/runtime/speech.go:643-660`)
   but every test and live run is narrator-only. Unit of work: (a) a synthetic

   asserting distinct `voice_id` per line and no cross-substitution; (b) a
   live e2e extension of `TestLivePlayUI`/the live speech session that
   approves a character voice (Wind Waker `ww:spk:<n>` linked via the
   ADR-0070 endpoint) and asserts the committed line spoke with it (ASR
   read-back + voice revision in the event); (c) a bench named-speaker metric
   that also records the voice used per line.
4. **G4 — Make research-only onboarding able to finish (blocks users without
   a disc).** Today: web-researched profiles are refused at publish
   (`internal/store/repo_publish.go:629`) and `parse_dialogue` refuses
   non-user-file sources (`internal/agent/tools/sources.go:222-224`). Unit of

6. **G7 — Player controls: pause/resume + narrated classes + mid-session mode

7. **G8 — Sign/item narration path + scenarios (degrades; release-gate item).**
