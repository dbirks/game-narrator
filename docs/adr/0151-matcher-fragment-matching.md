# ADR-0151: fragment-aware matcher scoring — containment, not similarity, for exact substrings of a script message

Date: 2026-10-21
Status: accepted
Owners: matcher-fragment worker
Related requirements/tests: ADR-0035 (the candidate matcher this extends — bounded retrieval, log-linear scoring, the abstain-first acceptance policy and its reason codes; the fragment path is one more reading of the shared-trigram evidence it already computes), docs/spec/05 ("Local candidate retrieval", "Clef adjudication and commit policy", "Timings"), docs/spec/12 (property-based and fuzz tests — NaN/infinite ranking values, deterministic ordering), docs/spec/16 (M2 timings: Rank p95 gate), `internal/matcher` (fragment.go, the `c.frag` floor in scoreOne, `fragN` in the acceptance policy)

## Context and constraints

On the board (2026-10-21) the OCR read real dialogue boxes but returned only a fragment of the box — one line, sometimes cut off mid-word, occasionally with a leading "| " from the box border and a junk trailing character. A ~30-character read turned out to be an *exact substring* starting deep inside a 105-character message; another was a substring at character 93 of a 208-character message (one long message spanning several boxes); a third was the first 16 characters of an 84-character message. Every one of these reads ABSTAINED (`message.candidates`, reason ABSTAINED, top scores -9 to -10, margins 0.11–0.20 against the 0.12 floor, 10 candidates in the pool), so each line committed unmatched, got no speaker, and was spoken in the narrator voice or not at all — with ~4300 messages in the profile.

The cause is measured on an invented 200-message corpus (no game text anywhere in the tests; AGENTS.md rule 5): the text component scores a contained fragment on the similarity metrics only, and similarity is the wrong reading of the evidence a fragment carries.

- Trigram Dice is symmetric, 2|S|/(|Q|+|C|). A 30-character exact substring shares all of its ~27 trigrams with the 105-character line and scores 2·27/(27+102) ≈ 0.42 — the length gap caps the score, not the evidence.
- The banded Levenshtein similarity is exactly 0: the 75-rune length gap is far past the 12-rune band, so the term reports "different line" for a verbatim window of it.
- Token Dice penalises the same length ratio.

The text component lands at 0.2–0.35, the log-linear raw score at -9 to -10, and the margin gate abstains. The evidence a fragment actually carries is *containment*: every character of the reading is in this line, in this order, in one place.

Constraints: a full-box read (the common case) must score exactly as it did before — the fix must not move any similarity case. Ambiguity must still abstain: a fragment that occurs in several lines (a generic phrase, a shared prefix) is not an answer no matter how well one line explains it. The board CPU is slow; the task budget is ≤ 15 ms per query on the development host at the board's corpus scale (~4300 messages), under the stricter 5 ms p95 / 10k corpus gate the scale tests already enforce.

## Options

1. **Widen the similarity band.** Rejected. Raising the Levenshtein band or re-weighting Dice toward the shorter string makes the symmetric metrics pretend to be asymmetric ones. A 30-character read inside a 105-character line is not a *similar* line — the similarity answer is "different", and forcing a number the metric does not have is how the next damage case sneaks in. The length ratio is not the failure; the evidence type is.
2. **Bag-of-words containment (set coverage over the whole line).** Rejected. Measured on the invented corpus: a 26-character read whose five words a *different* line all contains in another order set-covers 0.96 of the read's interior trigrams. Set coverage ignores cross-word trigrams — the trigrams that name word *order* — so a line that merely contains the read's words would count as a covering line, an ambiguous read would commit the wrong line, and a unique read could lose its uniqueness count.
3. **Windowed containment over the read's interior trigrams (chosen).** The read's interior trigrams split into word-internal (they name words) and cross-word (they name word *order*). A window of about the read's length contains cross-word trigrams only for words adjacent inside the window, so order is enforced for free, and the best window is also the evidence of *where* in the line the read sits. A set over the whole line cannot make that distinction; a window can.
4. **Ask the capture side for a longer read / retry the box.** Not the matcher's job. The box geometry is fixed by the game and the read width by the OCR; the matcher must do the right thing with the reading it is given, and the fragment case is the common board case, not an anomaly to work around.

## Decision

1. **One more reading of the shared-trigram evidence, applied as a floor.** `scoreOne` (score.go) computes the text component exactly as before (trigram Dice, token Dice, banded Levenshtein), then, when the candidate is *strictly longer* than the observation and the observation has interior trigrams, computes the fraction of the observation's interior trigrams contained in a single contiguous window of the candidate (`fragmentWindowCoverage`, fragment.go) and floors the text component with it: `text = max(text, coverage)`. It never ceilings — a damaged reading whose containment clears the floor keeps the higher of the two readings of the same evidence — and a candidate as short as the read is a similarity case, so the floor never applies to full-box reads and their scores are bit-identical to before.
2. **Interior trigrams only.** The observation's boundary-pad trigrams (the ones `trigramKeys` adds at both ends) are excluded: the pads name the read's own edges, which cannot lie in a line's interior, so counting them would cap containment for a read at a line's edge. The same exclusion is symmetric for the candidate. A read of fewer than three runes has no interior trigrams and cannot claim containment — the existing low-specificity gate is the honest answer for it.
3. **Three sliding window lengths, cheap prefilter.** `fragmentWindowCoverage` slides windows of length `qLen-1`, `qLen`, `qLen+1` because the read's length can sit at most a character off the window it came from either way (a trailing junk character makes it one longer; a box-edge trim the other). A slide moves the window by two trigrams — one leaves, one enters — each one hash plus one binary search over the observation's sorted interior keys, so each pass is O(len(candidate)) small steps. It runs only for candidates whose *whole-line* interior set already covers at least `fragmentCoverageFloor` of the read (`fragmentFloor`, the cheap necessary condition: a window is a subset of the line).
4. **The floor constant is 0.9, measured.** On the invented corpus the window coverage of the read's own message is: exact 25–40 character windows 1.000; leading "| " plus one junk trailing character 0.964–0.989; one interior misread 0.929; two interior misreads 0.857; a junk-only reading 0.000. 0.9 sits in the measured gap the same way `fuzzyTextFloor` sits in its measured gap: high enough that junk or half-corrupted readings cannot claim containment, low enough that the board's damaged reads still can. Raising it toward 0.95 would silently drop the damaged reads the board evidence shows are the common case.
5. **Uniqueness is policy, not scoring.** The per-candidate fraction says "this line explains most of the reading, in order, in one place" — it does not say "no other line does". The ranker therefore counts the pool candidates that clear the floor (`fragN`) and the acceptance policy (score.go, the low-specificity clause) abstains when `fragN > 1`, on the ground that the covering lines' text scores are near-identical by construction and no per-candidate value the ranking computes distinguishes them. The same escape hatches apply as for every other low-specificity case: real graph or deciding-scene evidence may still resolve it, and the abstain still returns the shortlist for a Clef call.
6. **The form merge is unchanged.** retrieve.go ranks the raw and box-edge-trimmed forms and keeps the better top score, ties to the raw, exactly as before the fragment path; the fragment evidence is computed per form inside that merge, so the winner's evidence is the evidence the commitment stands on.

## Tradeoffs

- **Fragment queries cost ~2x the similarity path (measured 0.584 → 1.145 ms/query, 4400-message corpus, this host).** The sliding passes and the per-candidate interior-key computation run for every candidate whose bag of trigrams already nearly contains the read, and a fragment's content trigrams are corpus-popular, so the retrieval pool is wider than a full-box read's. The budget is 15 ms/query on this host at this scale and the release gate is 5 ms p95 over 10k messages; both hold with a wide margin, and the cost is paid only when the reading is shorter than the candidates it could be contained in — a full-box read pays nothing new.
- **A unique-but-damaged read can still abstain.** Two stacked interior misreads (measured 0.857) fall under the floor and the read abstains rather than commit the wrong line. That is the intended direction of error: abstention costs a narrator-voice line, a wrong-speaker commit costs the line's meaning.
- **The ambiguity count is a pool count, not a corpus count.** `fragN` counts pool candidates; a covering line retrieval never surfaced would not be counted. The pool is the matcher's honest universe (bounded retrieval is ADR-0035's contract), and the tests' oracle (`fragAmbiguity`) counts over the whole corpus and requires abstention whenever the corpus says the read is not unique — the strict side.
- **The floor is a measured constant on an invented corpus.** It is the same shape as the existing `fuzzyTextFloor` and the other measured thresholds in the package; if a real profile's damage distribution disagrees, the constant and the tests move together, with the measured gap re-logged, and the behaviour policy (floor, never ceiling; abstain on ambiguity) does not change.

## Validation

- **Failing-first tests, invented corpus** (`internal/matcher/fragment_test.go`, `fragment_cases_test.go`; ~200 synthetic messages of 60–220 characters, all strings generated nonsense — no game text): an exact 25–40 character substring from the middle of a message (case a), a substring cut mid-word at the end (case b), the board's damage profile — leading "| " plus one junk trailing character (case c), a 3–4 character junk string that must still abstain (case d), and the generic shared phrase that occurs in every message and must abstain with a populated shortlist (case e). Each unique-fragment case asserts the commit rule the board reads failed: no abstention, the fragment's own message on top, margin at or above the 0.12 floor, and a text component ≥ 0.9 so the evidence reads as containment, not half-similarity. `TestFragmentNeverCommitsAnotherLine` is the fragment-side property: a corrupted fragment commits its own line or abstains, never a different line. All of these failed before the fragment path (the reads abstained, matching the board) and pass with it.
- **Race and regressions.** `go test -race -timeout 15m ./internal/matcher/... ./internal/session/...` (result in the task report) — the acceptance policy's new clause touches the commit path the session owns, so the session package is in scope.
- **Performance** (`fragment_bench_test.go`, the same 4400-message invented corpus the tests use, scaled to the board's ~4300): `BenchmarkFragmentRank4400` measures one `Rank` per fragment-shaped query (exact 25–40 character windows, every fourth with the damage profile), build excluded. On this host (i7-7700, 8 threads): **before 584,369 ns/op, after 1,144,849 ns/op** — 2.0x, ~13x under the 15 ms/query budget. The existing 5 ms p95 / 10k-message scale gate (`scale_test.go`) stays green in the package run.
- **Replay gate.** `make test-replay` (PASS/FAIL/NOT RUN counts in the task report) — the gate must stay green.

## Consequences and reversal

- **Consequences.** A unique fragment of a script message now commits its line with a passing margin instead of abstaining to the narrator voice; an ambiguous fragment abstains on a count the ranking would otherwise hide, with the shortlist still returned for adjudication; a full-box read scores bit-identically to before, and the abstain/reason codes, the margin gate, the graph and scene escape hatches and the predictive-prefix policy are unchanged in shape. The matcher gains one new file and two small clauses; no schema, index layout, retrieval bound, or provider seam changes.
- **Reversal.** Delete fragment.go, the `c.frag` block in `scoreOne`, the `fragN > 1` clause in the acceptance policy, and the `obsIntKeys`/`winCount`/`winPresent`/`fragN`/`intScratch` fields in retrieve.go; the four fragment test files are additive. The ranking falls back to the similarity-only text component and the fragment reads abstain again — the pre-ADR-0151 behaviour, with no persistence, cache-key, or fence change.
