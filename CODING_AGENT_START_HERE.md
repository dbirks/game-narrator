# Kickoff instruction for an autonomous coding agent

Implement the **complete Game Narrator** application defined in this repository's specification. Read `README.md`, `AGENTS.md`, `docs/spec/00-product-charter.md` through `docs/spec/18-decisions-and-risks.md`, `docs/test-plan/scenario-catalog.md`, and the initial ADRs before changing architecture. The work is **not complete** when a vertical slice speaks a sentence. The goal is a polished, self-hosted, multi-game product with a complete onboarding agent, recognition and voice pipeline, embedded React UI, extensive Dolphin E2E automation, diagnostics, release packaging and documentation.

You have permission on the designated Arch Linux development host to inspect/install necessary development tools through passwordless sudo, provided commands are relevant, logged and do not destroy unrelated user data. Dolphin and a legitimate user-provided GameCube image will be provisioned by the user. Model roles connect through user-supplied gateway configuration; do not invent endpoint addresses or store access secrets in Git.

**First actions:** inventory host/installed versions; check private prerequisites; verify actual Dolphin graphical rendering and controllable input with a capability spike; bootstrap Go+React+SQLite+event layer and test suite; create ADRs for any new technical choices; build synthetic fixtures for unblocked CI; implement the full work plan with tested incremental integrations. If the game or model gateway is not yet available, mark those live gates `BLOCKED` and continue all other engineering work; don't claim them to have passed.

During development, maintain status by requirement IDs and evidence: go/unit; replay; Playwright UI; real Dolphin (actual screenshot+controller acceptance); real decision/TTS/ASR; UNO Q physical. When a test fails, save the frame/trace/audio evidence, reproduce, fix and add a regression test. Generate linked HTML test reports. The developer panel must show the same dialogue occurrence and correlation IDs as actual Clef decision calls and speech events. Introduce no Wind Waker-specific conditionals in core code. Do not bundle copyrighted game/voice material. The application's approved voice references persist independently of GPU inference workers and are reconciled across voice-serving replicas.

Don't ask needless questions about decisions already made in the specs. Escalate only inaccessible credentials or game assets, ambiguous legal permissions, genuine blockers and irreversible publication/deletion. Keep records in `docs/adr/` before and during important architecture changes. The final handoff must contain functionality, real test commands/results, evidence artifacts, release artifacts, known limitations, validated environment matrix and any explicitly unverified dependencies.
