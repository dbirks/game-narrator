| Dolphin savestates (hotkeys over a second Pipes FIFO) | 2026-10-18 | The two-pipe approach was retired for a measured reason, not abandoned: with the chord bound to the controller pipe, Dolphin's SI polling thread (~120 Hz) and the HotkeyScheduler both read the SAME Pipe FIFO, so the chord byte is consumed by whichever reads first (consumer contention → nondeterministic firing); the second-pipe layout has the structural problems already recorded in ADR-0043. **Approach D (the working one, ADR-0043 amendment 7)**: the savestate hotkeys are bound to the KEYBOARD device instead — `Device = XInput2/0/Virtual core pointer` (the X11 keyboard device 2609's XInput2 backend resolves to, measured from the exit-rewritten spike user dirs; every keyboard controller resolves to this exact string), `Save State/Save State Slot 1 = \`F1\``, `Load State/Load State Slot 1 = \`F2\``, `HotkeysRequireFocus = False` — and the keys are injected with XTest (xdotool keydown/keyup, 150 ms hold) on the Xvfb display; the hotkey scheduler's own thread is the sole consumer of the key state and the controller FIFO keeps a single consumer. Two more measured findings: the savestate folder is `StateSaves/`, not `states/` (the old glob watched the wrong dir — the hotkey was firing all along), and the drive's slow-START boots hold the title ~2.5–4.5 min (the iteration cap went 90 → 200; the loop detector still fails fast on dead screens).
