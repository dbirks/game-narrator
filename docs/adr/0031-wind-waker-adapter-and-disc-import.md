# ADR-0031: Wind Waker reference adapter (internal/games/adapter/windwaker) + local disc import
Date: 2026-10-17
Status: accepted
Owners: david
Related requirements/tests: docs/spec/04-game-adapters.md (Wind Waker reference adapter, portability rule), docs/spec/02 (normalization and markup; per-game SpeechRenderingRules revision in audio cache keys), docs/spec/14 (IP policy; no game text committed or logged), `internal/games/adapter/windwaker` tests (synthetic BMG mapping/escape/render/skip-empty; env-gated real-disc `TestRealDisc*`), `cmd/game-narrator` `import-disc` tests (usage; env-gated end-to-end), ADR-0029 (the BMG parser this adapter maps), ADR-0027 (disc/RARC access)

## Context and constraints
docs/spec/04's portability rule forbids Zelda-specific logic in the core runtime, the parser plumbing or the UI; the game knowledge must live in exactly one place: the reference adapter. That adapter must turn the game's BMG message archive (from a user-supplied `.gcm`/`.ciso` disc, or raw `.bmg` bytes) into canonical `games.Message` rows with: a byte-faithful `original_text`, a lossless token AST as `markup_json`, a matching `normalized_text`, an editable `speech_text` produced by a versioned per-game `SpeechRenderingRules` table, and an honest dialogue-graph decision. Game text and bytes must never be committed, logged, or printed (AGENTS.md rule 5); tests on the real disc assert counts and ratios only.

The BMG parser (ADR-0029) already delivers the lossless token stream; this ADR decides the **mapping** from tokens to the four stored columns, the **escape grammar** for `original_text`, the **rendering table**, the **graph decision**, and the **local import path** the user runs against their own disc.

Structural facts relied on here (all verified against the user's own disc in ADR-0029 and the real-file test, numeric only): 4,411 entries; 4,320 non-empty; 91 empty/system entries (offset points at a terminator, so the token stream is empty or tags-only); 8,888 control-tag occurrences; the pool is pure ASCII plus `0x0A` (display line break) with no high bytes in this file; the file has **no FLW1/FLI1** section.

## Decision
`internal/games/adapter/windwaker` implements `adapter.Adapter` (ID `windwaker-bmg`, version `1.0.0`, schema `1`, formats `gcm`/`ciso`/`bmg`) with two entry points: `Parse(ctx, r, opts)` for raw `.bmg` bytes and `ParseDisc(ctx, *gcdisc.Disc, opts)` which extracts `res/Msg/bmgres.arc → first .bmg` (the exact path ADR-0029 validated) and re-checks the game id starts with `GZL` before parsing, so a mislabelled disc fails loudly rather than being imported under Wind Waker rules.

Message mapping (one row per non-empty entry, in INF1 order):
- `SourceMessageID` = the BMG message id as a decimal string — stable across re-imports and the key the store reconciles on.
- `OriginalText` = the raw pool bytes projected through a small, documented **escape grammar** (below); it re-encodes back to the exact bytes.
- `MarkupJSON` = the token AST as a JSON array of `{kind, offset, length, group, type, args, raw}`; offsets tile the raw slice with no gaps (asserted).
- `NormalizedText` = `textnorm.Normalize` of the text runs with control tags removed and `0x0A` display wraps folded to spaces.
- `SpeechText` = the text runs with the `SpeechRenderingRules` table applied.
- `TextKind` = `dialogue` for every imported row. The BMG INF1 attribute bytes carry **no reliable kind signal** in this file (the first attribute words form a per-message counter, not a class), so the adapter does not invent one; the only non-dialogue-looking entries are the empty/system ones, which are **skipped with a count** rather than stored as `other` (an empty `other` row could not validate anyway).

**Escape grammar for `original_text`.** A CP1252-like 1-byte encoding projected to a Go string the UI can display and the curator can copy, with a strict inverse so `decode(encode(raw)) == raw` and `encode(decode(s)) == s` for anything this package produces:
- text-run bytes: `0x00–0x1F → \xNN`, `0x7F → \x7f`; printable ASCII literal except `\`→`\\`, `{`→`\{`, `}`→`\}` (the braces are escaped *in text runs* — the tag placeholders' own braces are not — which is what makes the grammar unambiguous without a context-sensitive parser); `0x80–0x9F →` the CP1252 character where defined else `\xNN` (the five CP1252 holes); `0xA0–0xFF →` the Latin-1 character.
- well-formed tag → `{tag g=<group> t=<type> a=<args>}` (decimal group/type, lowercase-hex args); the raw bytes are `0x1A, 2+len(args), args`, so the placeholder reconstructs the exact tag.
- malformed tag → `{tag bad r=<raw-hex>}` (the full raw bytes, since a malformed tag has no dependable decomposition).
The encoder is a **total, strict** function: an unknown escape, a malformed placeholder, or a character with no byte is an error, so a corrupted or hand-edited `original_text` fails loudly instead of silently re-encoding to different bytes. The round-trip is asserted on the synthetic fixture and on 100% of the real disc's messages.

**SpeechRenderingRules** (`rules.go`) is *data, not code*: a flat table of `(group,type) → remove | space | newline | pause(ms) | player_name | button("A")`, versioned by `RulesRevision` (`v1`). Unknown tags default to `remove` (a deliberate, documented default: an unclassified tag must never invent speech). From structural inspection of the user's own disc (counts and contexts only — no message text): `(0,0)` is the player-name placeholder (`player_name`, 357×); `(0,7)` is the typewriter pause (`pause 250ms`, 1,209×; the args byte varies as a duration hint and is preserved in `markup_json` for a revision that scales by it); `(0,0x0A)`/`(0,0x0B)`/`(0,0x0E)` are the A/B/Z buttons (`button`, confirmed by menu context); the emphasis switches `(0xFF,0)` (5,232×) and colour `(0xFF,1)` are `remove`; the per-character voice/emotion codes (group 1) and speaker codes (group 2/3) are `remove`. The revision is stamped into `ParseResult.Warnings` (column `rules`) — `ParseResult` has no free-form metadata field, so the revision rides the warnings as a stable, greppable marker — and into `sources.coverage_notes`; that stamp is what audio cache keys derive from, so a table change is detectable as stale cache, not a silent voice change. The real-file test asserts the table covers ≥ 95% of tag occurrences by count (measured 99.9%) and logs the distinct `(group,type)` population on a regression.

**Graph decision.** The requirement is the negative one: `next` edges come only from a reliably-decoded FLW1/FLI1 structure, never from adjacency or a guess. The user's disc has **no FLW1/FLI1** section (ADR-0029), and no FLW1 decoder has been structurally validated, so the adapter emits **no edges** and records the exact note `graph: not decoded (FLW1 raw)` (the `GraphNote` constant) in `sources.coverage_notes`. A future revision that validates an FLW1 layout against the user's own files is what turns this into edges; until then every edge would be an invention.

**Local import (`game-narrator import-disc`).** A thin, honest CLI driver: the game-specific knowledge (which file, which tags, which region letter) lives in the adapter, not the command. Flags: `--data-dir`, `--image` (or `GAME_NARRATOR_GAME_IMAGE_PATH`), `--game-slug` (default `wind-waker`), `--publish`. It (1) resolves the image (never logged or stored), (2) opens it in place via `gcdisc` and checks the game id starts with `GZL`, (3) extracts + hashes the BMG, (4) creates-or-reuses the game (slug), the edition (region from the disc id's 4th character — `E→ntsc-u`, `J→ntsc-j`, `P→pal`, else `unknown`; the mapping is the user's own disc population, `GZLE01`=USA/`GZLP01`=PAL/`GZLJ01`=JPN — and language `en`), and a draft profile, (5) writes one `sources` row (`game_extract` / `user_supplied`, the BMG content sha256, parser `windwaker-bmg@1.0.0`, and a counts-only coverage note), (6) imports all messages in one transaction, and (7) stores the BMG bytes in the local content-addressed asset store only. It is **idempotent by content**: a re-run finds the existing source row (same BMG sha256) and reports the count instead of duplicating rows. `--publish` moves the draft through review and publishes it (re-reading the row version at each hop), off by default. The command prints counts, never text.

## Alternatives considered
- **Storing `original_text` as base64 or a hex blob**: rejected — docs/spec/02 requires a string the UI displays and the curator copies; a documented, reversible escape over the token stream satisfies byte-faithfulness and legibility at once.
- **A lossy `normalized_text` (OCR-fold)**: rejected — the matching key must be lossless; OCR folding is applied at recognition time, not import (docs/spec/02).
- **Emitting `next` edges from INF1 table adjacency**: rejected — entries are out-of-order with backward/zero pointers (ADR-0029), so adjacency is not flow; guessing edges would poison the dialogue graph.
- **Storing the disc image or the whole RARC in the asset store**: rejected — only the extracted BMG is stored (content-hashed, gitignored, local); the multi-GB image is never copied (docs/spec/14, AGENTS.md rule 5).
- **A separate, hand-rolled BMG reader in the adapter**: rejected — it would duplicate ADR-0029's bounds/tiling invariants; the adapter maps the parser's tokens instead.

## Validation
- **Synthetic BMG through the adapter** (`adapter_test.go`): a 5-message fixture (plain text; text with a player-name tag, a pause tag, an A button, an emphasis pair, an unclassified tag and a `0x0A` wrap; an empty message; a tags-only message; a truncated tag). Asserts the exact mapping (decimal `SourceMessageID`, the escape, the AST tiling, normalized/speech rendering), `original_text → exact raw bytes` for every imported message, the empty/tags-only skip count, the rules-revision marker and the graph note in the parse result, the size/row-limit and non-BMG rejections, `Detect` confidence, and the strict-encoder garbage rejections.
- **Real disc** (`real_test.go`, env-gated by `GAME_NARRATOR_GAME_IMAGE_PATH`, otherwise `NOT RUN`): parses 4,411 entries → 4,320 messages (≥ 1,000 guard against a section-walk bug), asserts 100% of `original_text` re-encodes back to the exact raw pool bytes, every `normalized_text` non-empty, `markup_json` present, and the rule table covers ≥ 95% of tag occurrences (measured 99.9%, logged with the distinct `(group,type)` population on a regression).
- **`import-disc`** (`main_test.go`): usage errors (no image → exit 2, unreadable image → exit 1, unknown flag → exit 2); env-gated end-to-end into a temp data dir asserts the store holds exactly the count the adapter parsed, the `sources` row is `game_extract`/`user_supplied` with parser `windwaker-bmg@1.0.0`, and the idempotent re-run reports without duplicating. `--publish` exercised manually: draft → review → `published`, 4,320 messages.

## Consequences and risks
- The escape grammar and the `(group,type)` table are Wind Waker-specific. A different edition or a hostile BMG with new `(group,type)` pairs falls to the `remove` default and shows up as a coverage drop in `TestRealDiscTagCoverage`, not a silent wrong voice.
- `pause 250ms` is a fixed middle of the observed range; the per-tag duration hint is preserved in `markup_json`, so a revision can scale by it without changing the escape.
- The region mapping covers the user's observed letters; an unrecognised 4th character reports `unknown` rather than guessing, since the region tag feeds compatibility checks.
- The `0x0A` display wrap is folded to a space in both columns (a wrap is layout, not a spoken pause); if a future revision finds a *real* newline tag, the `newline` rule action is already in the table.

## Reversal plan
Revert `internal/games/adapter/windwaker/`, the `import-disc` additions in `cmd/game-narrator/main.go` (+ its test), and this ADR. The adapter is additive (a new registry entry and a new CLI subcommand); nothing else depends on it. The store schema is unchanged, so a revert leaves no migration to undo.
